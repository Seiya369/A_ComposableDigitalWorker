# ADR-002：统一工作流定义与项目引用

日期：2026-10-25。状态：已采纳，自 0.26.0 起执行。官方宿主边界仍按 ADR-001。

## 问题与决定

旧实现把库定义复制进项目，菜单又追加库中已不存在的项目副本，导致两个入口的列表、名称和编辑结果不一致。现在 `workflowTemplates` 是唯一可编辑的工作流定义库；graph_horses 和对话菜单读取同一组 ID、顺序、名称和版本。对话选择保存引用，不建立第二份独立定义。

项目仍独立保存人员实例、权限、知识空间、当前步骤和验收历史。`ProjectWorkflow` 是按库定义及项目人员绑定维护的执行投影，不能作为另一组菜单来源。变更定义在存储原子事务中同步全部引用项目；不创建任务、不重放执行、不发模型请求。人员实例复用稳定 ID，新成员才创建项目实例；不会用库员工设置覆盖已有项目员工权限或私有资料。

## 版本、历史和并发

定义更新同时增加相关实例版本，旧步骤切换或验收请求通过现有 CAS 拒绝，不能把旧预览作为新定义提交。名称修改不改变已验收记录；步骤要求、顺序或负责人等执行契约改变时，受影响步骤及后续完成标记失效，需要重新验证，原始交付和验收记录仍保留。

运行中含排队、执行和阻塞状态的工作流拒绝定义更新或移除；整个写入回滚，不产生部分同步。已有交付的步骤或成员不能直接移除、替换负责人，需新增步骤或成员保留旧历史。项目当前步骤若仍存在则保留；被移除且无历史的当前步骤移至下一个未完成步骤。

库中移除定义会从菜单移除该引用；项目资料和历史不删除，但旧引用停止启动任务或切换步骤，界面提示改选其他工作流或“无”。定义一旦进入库引用模式，缺失不会被当成待迁移内容反复恢复。

## 旧数据迁移

开启旧存储时进行一次受锁与版本约束的事务：已有库定义的实例标记为库引用；旧项目独有工作流以原定义 ID、步骤、名称、成员映射和层级补入同一库。缺失的员工模板仅按已有项目记录恢复，既有员工不重复创建。项目原始实例、当前步骤、完成记录、运行、知识与对话选择保持；迁移可重复打开而不重复注册或重放任务。

迁移只修改本插件存储，不修改宿主会话、程序或依赖。安装验收应分别记录新增的库定义和引用标记，不能将这部分授权迁移描述为“整个状态字节不变”。

## 验证

检查菜单与库 ID/名称/顺序完全相同、编辑跨项目原子同步、CAS、运行中拒绝、历史保护、旧独有定义一次迁移、删除不复活及卸载重装数据保留。实际界面检查负责人使用当前步骤而非最后交付，旧状态行消失，折叠与图谱工具栏只影响阅读。最终包须独立完成官方原生及完整生命周期验证。
