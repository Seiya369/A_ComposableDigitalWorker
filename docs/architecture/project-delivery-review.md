# 项目工作流详情与交付验收

版本：0.25.0。旧项目工作区的项目选择、模板引入、团队卡片、五分区导航、工作台编辑器与任务图界面已删除。全局 graph_horses 主面板只显示自由职业人库、团队和工作流三类资源。

## 对话中的工作流

原生输入区上拉菜单只有“无”和可选工作流。选择继承、独立冻结安装、负责人路由及共享步骤按 `conversation-workflow.md` 执行。标题旁的紧凑步骤条使用灰、白、蓝填充圆点，名称置于圆点下方；显示不下的名称和步骤使用省略，右侧“详情”固定可见。

官方 DSH 0.2.1-alpha.2 没有标题上方整行附加槽。步骤条移入右侧、原生打开方式之前的公开 `conversation.session.header.utilities`，不重排原生标题或对话/轨迹，不替换原生头部，不修改祖先 DOM/CSS。独占顶行并整体下移原生内容需等待上游提供相应入口。

## 精简详情

“详情”打开本插件自有对话框，标题使用当前原生项目名称，下方通过“工作流 / 项目知识库”切换；不显示旧的右上 Wiki 和刷新入口。工作流视图默认读取当前步骤：

- 左侧保留工作流名称与完整步骤，窄轨道绘制真实配置的退回路径；未显式配置时不绘制默认返工环。
- 右侧第一段先显示步骤名称、状态与负责人，其下“步骤内容”带右侧三角，默认收起步骤说明；交付内容、验收标准、退回目标和可折叠的已规划任务摘要保持直接显示。
- 第二段“交付记录”只列当前步骤负责人的根交付，记录可点击查看对应版本；待验收仍可通过或填写原因后退回。
- 第三段“交付成果”列出当前展示交付的文档和有效已验收事项声明，点击展开保存的内容，不根据路径任意读取本机文件。

下拉选择仅查看要求；“设为当前”才改变激活步骤。验收通过/退回复用已有执行器规则，点击节点或普通 turn 结束不会伪造完成。相关任务仍是规划草稿，不自动启动、调度或发布；可在已规划任务中查看摘要。

读取使用 `GET /digital-workers/api/conversation-workflow/details?sessionId=...`，按原生工作区推导项目，可按 stepId/runId 查看已授权记录。界面点击历史时附带 runVersion，过期版本返回冲突，不自动改读新版本。DTO 显式列字段，只返回当前冻结流程与本会话旧独立交付，不透传员工模型、技能或完整项目状态。超长正文标明原长度和截断，可打开原会话读取完整交付。

确定事项使用随交付保存的 `*.confirmed-items.json`，媒体类型为 `application/vnd.composable-workforce.confirmed-items+json`。内容是 `{schemaVersion:1,items:[{id,title,content}]}`，最多50项、文档100k字符，拒绝重复ID、额外字段和越界文本。只有有效完成记录对应的已验收交付会提升这些声明；这表明该交付中的事项已随成果验收，不推断用户逐项确认。UI还按当前展示的run ID和版本筛选，避免历史文件混入另一版本的事项。

项目知识库复用当前冻结团队的共享知识空间，浏览、切换、缩放和阅读不调用模型；切换视图保留步骤选择与未提交验收说明。每个项目团队只持有资料与快照，共享同一包级 Wiki 程序。

验收使用 `POST /digital-workers/api/conversation-workflow/review`，核对原生 session、项目、实例与版本、当前步骤、负责人、根交付及其版本和工作区 revision。冲突后刷新，不自动重发用户验收。旧独立交付可验收，但不会推进新工作流。

## 兼容历史交付

运行底栏的“任务与交付”对当前工作流根交付直接打开同一安全详情入口；选择“无”或改选时提示先选择其所属流程及步骤，不自动改选。通用 run.review/run.cancel 拒绝对话工作流记录，避免绕过原生会话、忙碌状态和完整版本检查。子任务不单独验收或推进流程。

普通交付、结构化旧流程和 workTask 打开独立单条交付验收面板，分别调用原有权威验收服务。面板只读取所选工作单及其必要成果，不再显示旧项目五分区；旧 attempt 只读。返回时打开原生会话。

删除旧 UI 不删除 projects、projectTeams、employees、workflowRuns、workState、消息、知识或交付。这些仍是冻结实例、组织关系、派工、历史兼容和验收的持久业务数据。安装升级不重跑旧任务，不自动创建任务或发起模型调用。

## 生命周期

主资源库与单条验收注册为不同公开 main 面板；步骤条与输入菜单通过公开 list 插槽注册。卸载撤销所有注册、监听、定时器和样式，详情对话框随组件卸载关闭。实际原生 Session 与用户数据保留；完整卸载清理流程见 `integration/README.md`。

0.21 顶部空间按公开 utilities 自身宽度响应式扩展，右侧与原生打开方式控件保持36px（当前官方8px gap加本插件28px）；不能精确把左界锁到下一行轨迹之后，也不重排宿主两行。显式退回箭头在节点上方走最多三层轨道；省略或拥挤的边不虚构跨窗连接，真实目标保留在节点描述及详情。

## 0.25.4 步骤说明折叠

步骤内容标题位于步骤名称、负责人之后及交付内容之前，使用原生 `details/summary`。默认不设置 `open`，点击标题或右侧三角、按 Enter／Space 都可展开和收起唯一的步骤说明；交付内容、验收标准、退回目标和后续交付记录、成果不属于该折叠区域。

同一步骤切换历史交付及切换语言保留当前展开状态；成功读取另一会话、实例或步骤后以新的折叠区域默认收起。项目知识库视图往返重新显示工作流时恢复默认收起，但保留原有步骤选择和未提交验收说明。折叠不发起业务请求、模型整理或步骤激活，不增加持久配置。


## 0.25.5 详情节点状态

详情左侧工作流程复用对话顶部的双环圆和序号样式及颜色规则：未开始为灰色，已完成为白色，当前步骤为宿主蓝色。完成后仍显示步骤编号。查看选择使用行边框表达，与工作流实际执行状态独立；点击查看已完成或尚未开始的步骤不会把它显示成当前蓝色，也不会激活该步骤。
