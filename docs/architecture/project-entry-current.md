# 项目入口与运行展示

版本：0.21.0。项目身份来自官方工作区与原生会话归属，不接受客户端自行指定其他项目的会话。

## 原生对话主入口

输入区默认显示“工作流：无”，点击直接上拉列表，第一项“无”。选中后显示“工作流：名称”。首次非空选择创建独立的项目工作流、随附团队、员工和上下级关系副本，记录来源版本；之后复用本项目冻结副本。已有团队、旧工作流和待验收任务不覆盖、不重放。

用户已确认：首次非空选择作为项目默认并清除本项目前置空覆盖，使全部对话统一继承；之后在某个对话选择其他工作流或“无”只影响该对话。同项目同工作流共享当前步骤与验收记录。模板修改不自动覆盖项目配置。

顶部步骤条用灰色未完成、蓝色当前、白色已验收的圆点连接，名称在圆点下方，溢出使用省略，右侧固定“详情”。点击只选择当前步骤，正在执行时禁止换身份；详情中切换查看步骤不激活，需明确“设为当前”。DSH 0.2.1-alpha.2 公开位置是标题旁的 `conversation.session.header.utilities`，没有标题上方整行入口；空白会话隐藏标题，第一次发言后显示步骤条。该限制不通过修改宿主绕开。

普通输入在同一原生会话中交给当前负责人，保留附件、历史、原生工具、沙箱、审批、停止和重试。负责人读取其模型配置、必备技能、知识入口、步骤说明、交付内容与验收标准；委派仅限下级，跨步骤负责人咨询必须明确原因。模型自述不等于执行完成；人工验收真实交付后更新共享进度，拒绝按步骤配置返工并保留历史。

## 历史与辅助管理

全局 graph_horses 仅管理自由职业人、团队和工作流三类资源。旧项目工作区入口、项目选择、模板引入、五分区、团队卡片及工作台编辑器已删除。当前对话的工作流详情展示冻结要求、负责人、组织下级及最新交付，相关任务和交付历史折叠。当前工作流根交付底栏也打开该安全详情；旧流程与其他任务只打开单条交付验收页面。安装、任务、历史兼容和验收所需后端服务保留。代码清理不删除历史数据、用户项目文件、知识库或凭据。

已停止的旧独立员工根对话也可使用工作流并继承项目默认。旧“员工·待验收”栏从对话底部移除，记录与原状态保留，可在详情的交付历史中查看；子任务和结构化执行会话保持原执行器的限制。仍被插件持有的旧 Agent 经公开释放与恢复交还原生控制器，相同 Session ID 和日志保留。

行首 `@` 继续提供当前项目已启用员工的显式独立派工，输入中间的 `@` 由 Harness 原生引用处理；模板库职业人不会因名字匹配直接获得项目执行身份。选择工作流会先创建其项目员工，因此主路径无需手动逐个引入。

源码与规则：`src/domain/conversation-workflow.ts`、`src/harness/conversation-workflow-runtime.ts`、`src/client/conversation-workflow.ts`、`src/ui/ConversationWorkflow.tsx`；完整验收规则见 [项目对话工作流](conversation-workflow.md)。

“无”只解除工作流的负责人上下文、业务工具和模型覆盖，沿用 DSH 原生模型选择规则（包括最近使用的模型）。它不重置原生模型、不修改全局默认；用户在原生选择器明确改选后仍按原生选择工作。历史会话中的先前岗位与知识记录继续保留，不把“无”解释为清空对话历史。

0.21 顶部空间按公开 utilities 自身宽度响应式扩展，右侧与原生打开方式控件保持36px（当前官方8px gap加本插件28px）；不能精确把左界锁到下一行轨迹之后，也不重排宿主两行。显式退回箭头在节点上方走最多三层轨道；省略或拥挤的边不虚构跨窗连接，真实目标保留在节点描述及详情。
