# 项目工作台 · 0.4.0

工作台在官方 `graph_horses` 项目实例页面中提供目标、任务、成果和验收闭环。DSH 原生会话保留，用于沟通及查看执行细节；项目列表、看板、依赖图共同读取同一个插件业务状态。无需修改 Harness，也无需先绘图才能执行任务。

## 使用顺序

1. 打开 `graph_horses → 项目实例`，选择 DSH 已打开的项目，配置本项目人员及其模型、Skills 和权限。
2. 进入“工作台”，打开“目标与标准”，填写项目目标、范围、完成标准和并发数。创建成果后再将其中需要交付的成果指定为项目必交成果。
3. 在“任务”中新建任务，配置负责人、目标、必要输入、验收标准、前置任务及预期成果。或者从项目已有工作流“生成任务计划”，再调整任务和依赖。
4. 逐项点击“开始任务”，或点击“启动项目”按依赖调度。保存计划不执行模型；启动操作才可能产生实际模型调用和用量。
5. 在详情中查看执行尝试和成果，打开原生会话核查执行；提交成果后由项目负责人验收或退回。也可直接手动提交文本成果或项目内文件路径，而不执行模型。
6. 前置任务及当前成果验收通过后，后继任务才能执行。项目必交成果当前版本均验收且无未完成任务时，才能“确认完成”。

“暂停派工”阻止启动后续任务，已经执行的任务继续完成；单独“取消任务”中断该任务。需重新执行时，先检查已有产物并填写返工意见，保留原任务身份和全部尝试。

## 工作对象与状态

| 对象 | 保存的内容 |
| --- | --- |
| 项目目标 `ProjectBrief` | 目标、范围、人工完成标准、必交成果、项目状态和并发上限 |
| 任务 `WorkTask` | 稳定 ID、负责人、输入、目标、依赖、验收标准、必交成果、所用输入版本和全部执行尝试 ID |
| 成果 `WorkDeliverable` | 稳定 ID、生产任务、标题、当前记录版本和修订列表 |
| 成果修订 `DeliverableRevision` | 文本或文件引用、修订号、来源执行、所用输入版本、验收历史及失效原因 |
| 原生执行 `WorkforceRun` | 本次人员配置快照、执行状态、原生会话、输出、产物与用量；通过 `workTaskId` 归属稳定任务 |

任务可处于待执行、执行中、待验收、已验收、待处理、需重新验证或已取消状态。“待执行”且前置未验收时，界面显示等待前置验收。状态由命令及执行结果驱动，图形连线本身不执行任务。

项目显式启动后，只派发依赖就绪、人员已启用且明确选择模型的任务，受项目并发及运行时全局预算限制。同一员工仍串行，不同员工可并行。依赖必须属于同一项目，禁止自依赖和循环；负责人必须来自本项目。后继输入只包含已验收成果的授权摘要与文件引用，不复制其他人的私有记忆或完整会话。

## 成果版本与返工

每次提交成果新增修订，不覆盖旧修订或旧验收记录。验收绑定当前记录版本；用户看过之后如果其他窗口提交了新版本，原验收请求冲突，需要刷新后重新核查。任务验收同时确认当前必交成果；单独验收成果后仍须确认任务。

修改上游任务、重新执行或修订成果，会标记相关后继需要重新验证，保留原验收历史与失效原因；无关任务保持原状态。系统不自动重做已验收任务。需要返工时只重试受影响任务，并新增执行尝试，不能把依赖旧输入的成果直接当作使用新输入的成果。

原生 `write/edit` 使用官方工具实际返回的写后文本，`present` 在读取权限检查后保存有界文本快照，旧新建工具也保存实际写入内容。上限为 `min(maxFileBytes, 100000)` 字节，历史执行的文本内容独立保留。人工只填写路径时，或工具成果为二进制、超限及无法安全读取的文件时，仅保存项目内相对路径引用；工具会在 `mediaType` 标记无法提供快照的原因。此类路径引用不具有可回放的内容历史，需要另存版本文件或使用项目自己的版本控制。快照及文本成果内容保存在插件状态，不自动建立 Git 提交。

## 界面

- **工作总览**：项目目标、已验收数量、执行中、待验收、需处理事项、最近执行和项目动态。
- **任务**：列表、看板和依赖图；按关键词、负责人及状态筛选，可聚焦所选任务的上游依赖或下游影响。
- **成果**：当前成果列表、修订历史和版本关系图；区分同一成果的修订关系与所引用输入版本。
- **详情**：编辑任务、查看依赖与执行尝试、验收/退回、局部重试、查看成果及打开原生执行会话。

人员组织树继续表达汇报关系，与任务依赖、成果版本关系分别展示。依赖通过表单选择，不依赖拖拽操作。窄屏以相同任务/成果列表替代大画布，详情仍可查看关系。筛选、所选对象及未保存编辑草稿保留于当前插件页面内存，刷新页面或卸载清除草稿；保存的业务记录持续保留。

## 兼容、持久化与生命周期

工作台保存在插件专属状态 JSON 的可选 `workState` 中，包括目标、任务、成果、事件和幂等回执。旧状态没有该字段时按空工作台读取，不自动创建项目目标、修改已有岗位或启动模型。命令使用同一个带版本校验的原子写入器；相同请求 ID 的重试返回原结果，不重复派工或新增版本。

重启保留历史，暂停项目自动派工；运行中断的尝试标记失败供检查，不自动重放模型或工具请求。普通卸载保留全部业务状态，重新安装恢复；显式完整清理按归属移除插件状态，用户项目文件、成果文件和 DSH 原生共享会话历史保留。完整流程见 [安装与卸载](../../integration/README.md)。

原有顺序工作流继续使用其原执行状态和人工交接。生成任务计划复制当时的步骤、负责人及顺序依赖，得到独立可编辑任务；不会修改来源流程、创建旧流程运行或立即执行。旧 `@` 工作单和旧流程运行与工作台执行分别标识，不自动迁入任务图。

`graph_horses` v1 JSON 仍只交换职业人、团队和工作流配置；目标、任务、成果版本、验收、事件、执行尝试及记忆不进入该交换文件。安装包仍为 `dsh-plugin-composable-workforce-0.4.0.tgz`。

## 当前边界

本版提供人工可调整的任务依赖图和按已验收依赖派工，不会让模型自主改写项目计划，也未实现任意条件分支、循环、分布式队列或跨项目任务。成果及任务仍由项目负责人验收。模型、Skills 和工具必须在目标 DSH 实际可用；Bash/终端和未适配第三方工具不开放，详见 [官方能力接入](native-capabilities.md)。

安装兼容性与归档生命周期证据以绑定具体 `.tgz` 哈希的[验收记录](../../integration/verification.md)为准；领域测试与人工成果验收不能替代真实外部模型账号的任务完成验证。
