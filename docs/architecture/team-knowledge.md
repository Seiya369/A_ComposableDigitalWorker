# 团队资料管理员与三级知识库

团队资料管理员在团队中显示为系统角色，配有默认选中的复选框；它不占用可派发工作的员工岗位，不能被选为任务负责人或工作流步骤。启用时，它在新资料或任务记录产生后维护团队及员工各自的三级知识库；没有新内容时不持续请求模型。

团队模板和项目团队实例分别保存 `knowledgeEnabled`，旧数据缺省视为启用。实例创建时复制模板设置，此后独立调整。取消勾选立即停止该团队共享库和全部员工专属库的 A 归档、种子复制、来源退出索引和 B/C 编纂，并阻止向员工提供 C、读取 B/A 或回退注入旧项目/员工记忆；正在编纂的请求会被中止，迟到结果不得发布。取消团队也停止这些后台操作。关闭仅暂停跨任务知识，保留磁盘上已有知识文件，不删除原生 Session、任务记录或交付成果。

重新勾选后，可以从仍保留在插件领域状态中的任务记录、交付、配置和显式记忆重新整理 A 并更新 B/C；这不是补抓每条原生 Session 事件，未持久化的临时内容不能保证恢复。恢复时按当前资料及权限撤回失效来源，而不是直接信任关闭前的旧知识。没有 `ProjectTeam` 记录的历史员工分组，旧数据缺省启用；通过旧版团队实例化入口新建时也复制模板开关，此后按分组独立调整。只要该组任一成员明确关闭，整组知识都暂停，避免不一致字段绕过开关。

仓储写入在等待队列、取得写锁后以及原子提交前重新检查开关，关闭时取消尚未提交的 A 索引、种子和来源退出操作。关闭不会撤销此前已经完成的文件系统写入；例如新 A 原始版本文件已写完、活动索引尚未提交时，保留该不可变文件但不将其设为当前活动来源。

该能力遵守 [ADR-001](../decisions/001-official-plugin-boundary.md)：只使用插件自己的数据目录和官方公开服务，不修改 Harness，不直接操作原生 Session 数据库。

公开接入以已声明的 `@deepseek-ai/dsh-llm@0.2.1-alpha.2` 为依据，使用导出的 `LlmRuntime.stream(GenerateOptions)`，以 `provider`、`model`、`reasoningEffort`、`system`、`messages` 和 `signal` 发起单次请求；负责人默认模型通过现有 Session Controller 读取。官方源位置见 [LLM 服务](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.2/packages/llm/llm/src/index.ts)与 [GenerateOptions](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.2/packages/llm/llm/src/types.ts)。知识仓储、管理员队列和扩展后的 `worker_memory_search` 是本插件能力，不是新增的宿主官方接口。

## 知识归属与目录

知识目录使用 `knowledge`，而非含义不明的 `.Hdata`。数据保存在插件的状态目录旁，不在用户项目工作目录里建立隐藏目录。实际根目录由 `statePath` 唯一确定：

```text
resolve(dirname(statePath), 'knowledge', basename(statePath))
```

默认 `statePath` 为 `<DSH_HOME>/composable-workforce/state.json`，对应：

```text
<DSH_HOME>/composable-workforce/knowledge/state.json/
├── .owner.json
├── templates/<team-id>/
│   ├── team/
│   │   ├── A-sources/
│   │   ├── B-knowledge/
│   │   ├── C-overview/
│   │   └── snapshot.json
│   └── employees/<member-id>/
│       ├── A-sources/
│       ├── B-knowledge/
│       ├── C-overview/
│       └── snapshot.json
└── projects/<project-id>/teams/<project-team-id>/
    ├── team/
    │   ├── A-sources/
    │   ├── B-knowledge/
    │   ├── C-overview/
    │   └── snapshot.json
    └── employees/<member-id>/
        ├── A-sources/
        ├── B-knowledge/
        ├── C-overview/
        └── snapshot.json
```

中文名称分别为“团队共享库”“员工专属库”“A 原始资料”“B 详细知识”“C 知识综述”。目录用稳定 ID 定位，名称修改不会改变归属。模板团队和每次项目安装各有独立空间；两个项目安装同一模板，也不会共享写入。模板用于维护通用种子知识，项目运行产生的记录不得反向写入模板。

每个 `A-sources` 实际创建并使用六类子目录；一个来源版本只存一份，定位仍使用来源 ID 和版本，不让模型输出成为文件路径：

```text
A-sources/
├── index.json
├── 01-reference/<encoded-source-id>/vN.json
├── 02-requirements-decisions/<encoded-source-id>/vN.json
├── 03-task-evidence/<encoded-source-id>/vN.json
├── 04-incidents-reflections/<encoded-source-id>/vN.json
├── 05-environment-constraints/<encoded-source-id>/vN.json
└── 06-preferences-capabilities/<encoded-source-id>/vN.json
```

分别对应专业资料、需求与决策、任务证据、失败与反思、环境与约束、偏好与能力。在员工“知识与记忆”中为显式来源选择“资料主类别”；没有选择的旧资料和通用确认记忆默认专业资料，不能根据标题出现“偏好”就擅自确认用户偏好。共享目标归需求与决策，正常执行/成果归任务证据，失败或取消的运行归失败与反思；分类本身不提高事实可信度。

界面依次使用“投喂马料、需求决策、任务证据、失败反思、环境约束、偏好能力”六个小标题，每项说明最多两行。第一项提供资料上传；编纂规则折叠保留。分组中的手工来源不代表 A 全部自动记录的数量。

“上传资料”使用单独的认证同源命令，不提交岗位、权限或未保存草稿。仅向当前已保存的团队成员私库入库；新员工、未分团或无法唯一确定成员的页面需先保存/进入具体团队。模板与项目实例各自定位，资料管理员或员工记忆关闭时拒绝上传及列表读取，不自动创建员工、团队、会话或共享权限。

上传支持可读 PDF、DOCX 和常用 UTF-8 文本，原件与提取文本分别最多 1 MiB。原件以 `originalFile` 随不可变 A 版本保存原字节和 SHA-256；`content` 为提取文本，PDF 带页码、DOCX 带段落标记，`text` 再做阅读规范化。原件哈希与解析器版本记录在来源中，分类仍为专业资料且未经核验。相同原件及元数据重复上传复用版本；文件名/解析结果等变化生成新版本。工作 agent 和模型只取得文本及原件元数据，不接收 base64。

上传结果只确认 A 已落盘，B/C 在后台按有效政策整理；编纂输入超限时原件仍留在 A 并报告待整理。上传列表展示实际 A 的标题、版本和原件标识，刷新可恢复。多文件逐件处理，部分成功必须列明结果。

PDF 最多 200 页，不支持扫描 OCR 或加密 PDF；DOCX 提取正文及表格中的段落，不处理图片、页眉页脚、脚注、删除修订和复杂版面，不读取外部关系目标。旧 DOC、宏文档、乱码、无可读文字、非法 ZIP/XML 或超限内容明确拒绝。页/段落是解析文本定位，不能冒充版面精确坐标；原件保留用于人工核对。

启用库初始化会在插件写锁和路径保护下恢复旧的平铺来源目录，覆盖活动、退役及未进入当前索引的已落盘历史，保留原文件字节、来源版本、哈希及阅读坐标。相同 ID 改分类生成新版本，历史版本可位于原类别。中断后可重复恢复，发现不同字节的目标冲突、非法目录、重复版本或链接则停止；不会覆盖原件。关闭资料管理员时不执行目录初始化和迁移。

启用的项目知识空间首次初始化时，可以复制与安装版本精确匹配且已启用的独立模板 A；员工空间还检查对应成员模板版本。关闭的模板不作为旧知识种子读取。员工配置和团队说明已由实例保存快照，不以另一个资料 ID 重复复制。B/C 在项目空间内重新编纂，不共享模板的可写快照。如果模板已更新到不同版本，不使用新版资料冒充项目安装时的种子。`seed.json` 记录首次种子状态，即使为空、模板关闭或版本不可用也不在以后重新跟随模板；从实例撤回配置后不会因重启而复活。

根目录的 `.owner.json` 固定记录包名、归属格式版本和完整根路径。不同 `statePath` 具有不同根目录；完整清理只处理当前状态对应的、归属标记有效的根目录。

## A、B、C 的职责

| 层级 | 内容 | 引用方式 |
| --- | --- | --- |
| A 原始资料 | 原始文本 `content`、规范阅读版 `text`、来源、版本、SHA-256、采集时间、验证状态、处理记录 | 来源 ID＋资料版本＋阅读版起止行号 |
| B 详细知识 | 从多份资料重组的解释、方法、关系、比较、适用条件、争议和未知事项 | 每个条目必须引用一个或多个有效的 A 版本及行号 |
| C 知识综述 | 概念/实体入口、主题综述、关键原则和结论 | 每个综述条目关联同一知识快照中的 B 条目 ID |

A 保存可核查的资料，不把 LLM 的推测改写成原文。B/C 的模型综合结果保留 `candidate` 状态，即使输入资料已验收，也不因此成为人工确认的事实或任务验收结论。资料中的命令和提示词仍是资料，不能改变工作 agent 的岗位、权限或用户指令。

文本资料先检查必填来源信息、容量、主类别和 ID；以原文哈希识别同一来源的重复录入，再规范 BOM、换行和 NUL 字符。原始 `content` 保留，规范版及 `processing` 说明同步保存。内容、来源、标题、分类、分类依据或验证状态变化会形成新版本，旧版本继续可引用。

这些处理不等于跨来源语义去重、OCR、音视频转写或自动事实核查。上传解析的已支持格式及定位边界见上文；矛盾、失败和少数观点属于有效资料，不作为噪声删除。

## 按专业与任务组织 B

员工“知识与记忆”新增专业说明、任务范围、概念提取规则，以及 B 的分类 ID、名称和说明。B 依据这些规则及岗位职责、技能、授权任务上下文重组，**不照抄 A 的六类来源目录**。例如支付岗位可设置“回执与幂等”“重试与恢复”，而财务岗位可使用“现金流预测”“成本归因”。B 仍保存带 A 引用的详细条目，分类是结构化元数据，不创建模型命名的磁盘路径。

显式分类 ID 以小写字母开头，只含小写字母、数字、连字符，最长 64；改显示名称时保留 ID。最多 24 类，名称 1–120、说明最多 2,000 个 UTF-16 字符。专业说明、任务范围、概念规则分别最多 2,000、4,000、8,000；保存及导入使用同一严格校验。旧员工缺省采用岗位规则，空分类从职责派生专业入口，并提供专业基础/原则与任务经验/核验入口；可用“恢复岗位默认知识组织”移除定制。

团队共享编纂只使用共享目标及成员岗位概要，分类带成员命名空间；不混入员工私有来源正文和私有概念补充规则。模板采用和配置交换保留规则，项目实例仍独立于后续模板修改。

编纂政策有独立指纹，并随 B/C 快照保留历史身份。仅修改专业或分类规则也会触发重编；旧政策晚到结果不得发布。重编失败保留磁盘历史，当前 C 降级为待编纂 A 索引，默认 B 不继续提供旧政策知识；显式历史读取标记过期，不能把历史政策当现行规则。任务中已固定注入 C 时，明确规则变化后下一模型调用停止，要求以新工作单取得新上下文；普通新增资料不因此中断当前任务。

概念提取要求稳定标识、别名与同名消歧、定义边界、版本与适用条件，保留否定、例外、冲突和未知事项；反思及原因猜测始终按提案描述。引用结构、分类和政策身份可以确定性检查，原文是否充分支持每条语义结论仍需独立证据或专业复核。该配置没有实现完整概念注册、逐命题事实证明、反思自动晋级或 TTL/单条物理删除系统。

## 编纂与读取

维护过程遵循“先 A，后 B/C”：

```text
新资料或任务结束记录
  → 检查、规范化、幂等录入 A
  → 收集同一知识空间的当前 A 版本
  → 使用资料管理员模型生成候选 B/C
  → 检查 A 引用行号、B 条目关联和资料指纹
  → 保存不可变版本，最后切换 snapshot.json
```

B/C 用同一个快照版本发布。读者通过 `snapshot.json` 看到完整版本，不能读取正在写入的一半；如果编纂期间 A 已变化，拒绝发布旧结果并重新编纂。链接存在和行号合法是结构检查，不能证明原文在语义上支持结论；候选状态必须保留。

归档使用短队列，编纂按团队隔离，同一团队的共享库与专属库串行处理，其他团队的慢模型不阻塞当前团队。文本、来源数量、模型输入输出和编纂时间均有上限；当前单次模型输入上限为 100,000 字节、输出上限 6,000 token，超限保留 A 和上一版知识并明确报错，不截断资料后假装处理完整。尚无 B/C 时，提供标明待编纂的 A 标题、ID、版本索引，工作 agent 可以通过工具回查原始证据。

删除配置、记忆或撤回成果验收时，来源退出 A 的活动索引，原始版本保留用于审计，相关旧 C/B 暂停使用并等待重编。文件知识也受当前文件工具、配置和读取范围约束；权限收窄时不再将其原文或派生知识提供给工作 agent。一次任务更窄的授权不会全局删除其他已授权任务仍需使用的资料。

模型选择绑定团队唯一负责人实际使用的 `provider`、`model` 和推理配置，管理员没有单独模型设置。负责人调整模型后，后续编纂使用新选择。负责人缺失、存在多名负责人或模型不可用时，不猜测其他模型，保留资料并等待有效配置。

这里的负责人按团队协作树中唯一顶级成员确定。`override` 复制负责人选择；`inherit` 与工作 agent 一样通过官方 `sessionController.modelCatalog().default` 解析 DSH 当前默认模型。默认缺失或不可用时不另选模型。只更换模型不会立即产生收费编纂，后续新增资料使用新模型。启动时只为启用的团队整理历史资料，仅归档 A；新事件产生资料变化后更新 B/C，任务启动前也会准备当前员工可见且需要更新的知识。编纂失败保留 A 和上一份完整快照，在后续事件或刷新处理中重试。

资料事件包括任务执行结束、待验收、验收、失败、取消，以及记忆和配置变化。员工私有来源只进入本人的专属库；团队共享库保存可共享的任务目标和已验收成果。首次实现对 URL 保存来源引用，不自动抓取远端正文；项目文件由执行时的授权文件读取机制取得，随后归档到相应员工空间。

工作 agent 默认获得相关团队共享库和自己专属库的 C，连同本次任务目标、输入、验收标准、岗位及硬约束。工作涉及某个概念、实体或方法时，必须在关键判断前读取 C 指向的 B；遇到冲突、证据不足或需要准确原文时再读 A。B/A 复用受权限检查的 `worker_memory_search` 工具，通过 `layer`、`knowledgeId`、`library` 和 `version` 指定来源及版本，不能读取另一个员工的专属资料。没有额外增加员工工具授权；工具须已在员工权限范围内，读取路径不构成额外授权。

既有项目记忆和员工记忆仍保留原有授权与显式写入规则。三级 Wiki 不替代任务状态、交接或成果验收，也不能把普通任务完成自动改成“已验收”。

## 员工每次模型请求的上下文

一次实际模型调用包含以下几类信息；不是把 C 当作全部上下文：

| 信息 | 当前实现的内容与进入时机 |
| --- | --- |
| 身份与职责 | 项目、员工及配置版本；使命、职责和边界，来自本次运行的项目实例快照 |
| 权限与协作 | 工具及参数定义、可读写路径、网络与 Shell 限制、可委派员工名册、委派深度/并发与上报规则；执行前还会检查当前授权 |
| 技能 | 当前员工已选 Skill 的名称、描述及正文，启动时载入 |
| 任务与输入 | 当前请求；项目任务或工作流还带目标、输入要求、成果要求、验收标准、反馈及已验收前置成果 |
| 交付规则 | 岗位交付标准、真实性要求和待验收要求 |
| 知识入口 | 开启长期记忆且有权限时，按当前任务选取团队与员工 C 的概览、版本、候选状态和 B 引用；待编纂时提供 A 元数据索引 |
| 按需证据 | B 提取相关原段，A 按版本及行列区间原文分页；工具结果进入后续上下文，旧知识结果按累计限额收拢 |
| 本任务历史 | 当前原生 Session 保留的任务消息、员工回答、工具调用及结果；新任务创建新 Session，不复制来源会话或同事全部聊天 |

模型、提供方、推理力度属于调用设置，工作目录属于会话元数据。它们与以上文本一起决定运行，但不属于知识 C。关闭资料管理员后仍提供身份、职责、权限、技能、当前任务及显式配置的任务资料；不提供旧长期记忆及其检索/写入工具。若关闭时任务已经注入知识，或已经接收包含该团队知识的委派结果，下一次模型调用前停止该任务，需要以新工作单取得关闭后的上下文；不会声称可以从原生历史中撤回已发送内容。

## ABC 激活与上下文限额

C 在任务启动时按目标选择，一次运行中复用；完整库内 C 不为每轮预算反复改写。任务需要详细解释、方法或判断依据时读关联 B；C 未列出的主题也可通过 query 搜索 B。检索索引仅用于导航，不能当成已阅读正文。

A 在下列条件读取，工具参数 reason 必须明确取值：

| reason | 激活条件 |
| --- | --- |
| quote | 用户要求逐字引用、原话或原始措辞 |
| exact-detail | 需要准确数值、单位、命令、接口、代码或阈值 |
| conflict | B 有冲突、历史方案、版本差异或状态不明确 |
| verify | 用户要求核验，或需要检查模型候选结论的原始依据 |
| missing-evidence | B 缺少必要条件、例外、支持证据或完整引用 |
| source-comparison | 需要对照两个或多个来源，保留各自范围和优先级 |
| no-wiki | 尚无可用 B/C，或搜索 B 后仍无相关知识 |

优先按照 B 的 citations 指定 sourceId、sourceVersion 和行范围，并保留邻近条件。用户已经指定原始资料且需要核验时，可以直接进入 A。B 无覆盖时，使用 worker_memory_search({query,layer:"A"}) 仅搜索授权 A 标题与元数据；指定来源、版本及 reason 后才返回原文。核验现行决策时需区分历史版本与当前状态。

| 层级 | 常用额度 | 单次/在场硬上限 |
| --- | ---: | ---: |
| C | 2,000 | 3,000 |
| B 单次读取 | 按相关原段选择 | 3,000 |
| B 当前上下文累计 | 按需保留 | 8,000 |
| A 单次读取 | 保持原文分页 | 2,000 |
| A 当前上下文累计 | 按需保留 | 4,000 |
| ABC 合计 | 各层共享 | 12,000 |

以上单位为**完整序列化知识包的保守 token 估算上界**：当前默认计算 UTF-8 字节，包含原文、引用、定位、标题、分页入口和其他元数据；不是所有模型的精确 tokenizer，通常比实际文本 token 数更保守。计数模块可注入精确计数器，但当前运行使用 utf8-byte-upper-bound，不用字符数除以 4 冒充中文精确计数。

团队与员工库共享一个预算。ABC 总限额还受模型窗口约束：不超过（上下文窗口－输出预留）的 25%，并留出岗位、技能、任务、工具定义、历史和安全余量。输出预留默认 min(8,000, window/4)，同时设置为实际模型调用 maxTokens；窗口元数据缺失时使用 64,000 的明确 fallback。无法容纳固定规则或当前任务历史时明确失败并要求缩小阶段，不截断非知识记录后继续。存储字节限制、管理员 6,000 tokens 生成上限、任务树累计 120,000 tokens 停止预算均不等于这里的限额。

B 使用任务相关原段抽取，A 使用原文窗口及分页；两者都保留版本、行号，部分行附一基 UTF-16 列号（结束列不含）。truncated 表示没有完整读取，A/B continuation 可原样回传 cursor。大 B 引用列表可用 citationOffset 分页。普通检索结果不返回指向虚构索引文档的 cursor，省略时需细化 query。旧确认记忆的详细入口使用独立 legacyMemoryId，避免与真实 A/B 中合法的 memory:* ID 混淆。

每次模型调用前，只对本插件知识工具结果执行官方 compaction/prune 与 tool/result 的 surfaceOp:replace；原始结果不删除，替换保留消息身份、工具关联和事件引用，原生 Session 可独立重放。重复内容仅保留一份正文；旧 B/A 收拢成可重读的 ID、库、版本及分页入口，其元数据仍计入预算。C 固定占额，不能假装淘汰仍在 system prompt 中的 C。最小引用本身耗尽额度时要求阶段交接，不宣称可以无限保留历史。

运行配置可在本插件配置中覆盖 knowledgeCMax、knowledgeBReadMax、knowledgeBActiveMax、knowledgeAReadMax、knowledgeAActiveMax、knowledgeTotalMax，均为正整数。默认值来自 14 类合成任务、三档预算的检索与独立答题评估；12K 保留全部 65 项关键证据及引用，18K 未增加主要任务完成数，紧凑 6.2K 缺少复杂任务证据。这不是任意任务或任意模型的最优证明。报告保存在源码仓库 artifacts/knowledge-context-budget-2026-10-21；答题采用当前 Codex 默认模型、预设检索路线，并非真实团队负责人模型或自主激活测试。

## 与 DSH Session 的区别

### 2026-10-22 的大型任务候选验证

针对较大输入窗口，新增**离线候选**：ABC 日常目标 32,000、48,000 触发可选内容整理、64,000 硬上限；C 目标 4,000、上限 8,000，B 单次 8,000，A 单次 4,000。当前任务必需证据不因达到 32K 而淘汰；超过硬限明确要求阶段拆分或另行调整预算。候选总额还取不超过输出预留后窗口的 20% 及其他输入占用后的剩余空间。K=1,000。

该控制器位于开发评测脚本，不是当前运行配置。试验使用真实 `tiktoken/o200k_base` 参考分词，完整计入序列化知识包和回读导航；没有证明它与 DSH 所选模型的 tokenizer 相同。正式运行仍使用上表的 UTF-8 上界默认值，不能把配置数字直接解释为模型精确 tokens。

8 个大型合成任务、4,128 条业务记录的预定路线试验中，12K、32/48/64K、96K 分别完整保留 0/8、7/8、8/8 任务的全部阶段必需证据。约 51K 必需原文在 64K 内完整保留，实际活跃约 54K；约 86K 原子证据在 64K 明确拒绝，96K 可容纳。另有模型固定快照答题探针；这些结果不能替代目标员工模型自主检索、实际项目和长期编纂验收。源码评估记录见 `artifacts/knowledge-budget-large-2026-10-22`。

资料分类、员工和管理员分工、概念与原子命题、逐条证据和失效传播的建议见[员工知识政策设计稿](employee-knowledge-policy.md)。其中待实现部分不会因本文描述而自动生效。

| 维度 | DSH Session | 团队/员工知识库 |
| --- | --- | --- |
| 主要用途 | 一次会话或执行的对话、工具调用及过程恢复 | 跨任务保存资料、知识综合和知识入口 |
| 组织方式 | 按会话和事件先后顺序 | 按团队、员工、主题、来源与知识版本 |
| 默认上下文 | 由原生会话及 agent 执行机制管理 | 默认注入 C，按需读取 B/A |
| 权威性 | 记录实际发生过的会话与工具事件 | 保留来源和候选结论；不独立决定验收 |
| 数据归属 | Harness 原生共享记录 | 本插件专属文件 |
| 完整卸载 | 保留，不直接修改原生 Session 数据库 | 用户选择完整清理时移除 |

一次任务的摘要和验证结果可以成为 A 的来源；这不意味着复制整份 Session。资料管理员的团队内系统角色展示不创建员工记录、工作单或原生 Session，也没有轮询计时器；其知识编纂通过团队负责人选择的模型完成。关闭资料管理员后，员工执行当前任务所需的原生会话历史仍由 Harness 正常管理。

## 生命周期与完整清理

普通官方卸载停止插件的管理员队列、运行句柄、订阅和后续模型请求，知识文件保留以便重装。只有用户选择 `purge` 完整清理时，才删除插件专属状态和知识根。停止 Harness 后先预览，再执行：

```sh
node scripts/plugin.mjs purge --dry-run --home /absolute/dsh-home --profile web
node scripts/plugin.mjs purge --host-stopped --home /absolute/dsh-home --profile web
```

若配置自定义 `statePath`，两次命令均增加 `--owned-state-path /absolute/state.json`；该参数必须与插件配置完全一致。该参数声明待清理状态的归属，不允许扩大到其他路径。具体服务日志只在提供 `--service-root` 后按原有规则处理。

知识清理先验证根目录归属、目录结构、普通文件身份和逐文件哈希，执行前再次扫描核对；拒绝符号链接、文件硬链接、未知归属、活动写入锁和预览后变化。删除使用已验证文件列表逐个移除，再从内向外移除目录，归属标记最后删除。即使状态文件已经丢失，只要知识根的归属仍可确认，也可规划清理。未通过验证时停止，不改用无边界的递归删除。

完整清理保留用户项目、已交付成果、原生 Session、共享凭据、其他插件和其他状态对应的知识目录。安装或升级不会触发历史数据清理。功能及清理测试不能代替 [ADR-001](../decisions/001-official-plugin-boundary.md) 要求的干净官方发行版、独立 profile 和归档哈希验收。
