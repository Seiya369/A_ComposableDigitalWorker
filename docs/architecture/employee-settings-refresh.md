# 员工设置与认知记忆改造

日期：2026-10-22；认知记忆布局及图谱更新于 2026-10-24。依据用户要求，在现有工作区增量实施；不修改 Harness 程序文件。

## 设计约定

- 团队页成员树和组织图仅展示，名称、汇报关系和成员增删在主区编辑；三个模板页顶部不显示配置范围切换、全局 JSON 或刷新，在对象标题栏统一提供移除、导入、导出和保存。团队名可直接编辑，副标题为“组织结构”；删除组织／工作流页签与齿轮，资料管理员大卡改为标题栏右侧的紧凑开关。开关只修改草稿，随保存生效；取消三个模板页“还原修改”，确认放弃后离开恢复保存状态。移除、导入、导出与保存移至标题栏右侧，移除团队及岗位均先确认；移除成功只清理当前团队草稿。删除添加员工入口与引入标签，选择框为“选择要引进人员”。主区岗位使用“团队岗位”“上一级”紧凑字段，两张成组卡片一行，窄容器单列；旧简介、工作流和已保存成员数据保留。旧团队成员导航缓存回到所属团队，新建员工保存后返回组织结构页。
- 员工按模型配置、岗位定义、能力组合、认知记忆排列四页，点击员工默认打开模型配置。兼容旧数据字段，不直接删除用户历史配置。
- 自由职业人库标题栏“移除”沿用既有 `template.archive` 命令隐藏模板，保留配置、团队引用和已有项目实例；确认取消零请求，成功只清该员工草稿。员工／团队／工作流均使用[对象设置交换](object-settings-transfer.md)：严格校验兼容格式，导入覆盖当前草稿，保存才原子更新目标与新依赖。
- 岗位角色标签行右侧的“AI智填”与输入框右边缘对齐，按当前员工草稿的姓名和模型一次生成岗位角色、工作职责、工作规范与边界。支持未保存的新员工和模型选择；跟随默认时读取 DSH 当前默认模型，不回退其他模型。结果只写入可编辑草稿，用户点击保存配置后才持久化。姓名、模型或岗位文字变化、导入、保存、切员工或卸载时取消请求并拒绝迟到结果；失败保留原值并可重试。
- 能力页使用必备 Skill（每次任务）、优先 Skill、优先插件、优先 MCP 四组简洁列表，各自通过 ＋／－ 添加和移除。插件按已装包选择，MCP 按已配置服务选择，选择窗口按需显示。
- 必备 Skill 在每份工作单开始时加载；优先 Skill 根据业务场景优先采用。其他原生可用能力仍可按需调用。插件、MCP 只记录优先使用偏好，历史工具偏好保留兼容。
- 原生能力与执行授权通过官方 DSH 预设、沙箱与审批机制提供，不再维护员工文件、Shell、网络工具授权表。任务验收仍属于任务和成果版本。
- 认知记忆主区使用[共享 LLM Wiki](shared-llm-wiki.md) 程序显示语义概念图：圆点只代表概念或实体，连线只来自 `conceptGraph.relations`。同端点多个有向谓词合并绘制、完整保留；没有关系的节点保持孤立，不按文章共现或共享来源补线。全项目只下载、打包和运行一套共享核心，各员工、团队只有隔离的数据。
- 图谱默认以二维分组总览紧凑显示全部连通组；分组包络只作视觉提示，不添加节点或关系。支持搜索定位、拖动节点、移动画布、缩放和适配视图；节点相对大小按原始语义关系度数计算，社区只按语义图划分。统计为概念数、实体数和实际关系数，默认使用知识分组图例，可切换节点类别区分概念／实体。选择概念突出一跳邻居，沿概念打开右侧 B 文章及精确 A 证据保留焦点，推断明确标记；来源、文章、概览不进入主图，从概念继续阅读关联正文与证据。清空搜索、清除选择或换库解除焦点。旧快照无概念图但已有文章时自动打开只读目录；A 原件与历史 B/C 不覆盖。
- 四类位于主图上方一排：专业知识、任务档案、复盘经验、工作约束。专业知识右侧为“上传资料”按钮，打开原有专业资料管理窗口，提供“查看”“－”及上传“＋”。其余三项各有独立“自动归档”开关，不作图谱筛选或跳转。关闭只停止后续自动收录和更新，旧 A/B/C 继续保留、可读；开启不立即调用模型补扫。主区不显示用途注释、数量、旧工具栏和导航，为图谱及正文留出空间。底部保留紧凑单行“影子员工资料管理：A 原始资料 > B 知识重组 > C 概念综述”。
- “上传资料”保留原件与 A 来源后增量整理 B/C；尚无编纂快照时也可先阅读 A。团队资料由资料管理员整理，个人知识由独立提示词的影子整理员整理；二者不占业务员工岗位，不混用业务对话上下文。
- 自动资料以任务阶段终点合批：待验收仅本地归档，验收定稿、失败、取消等稳定节点才编纂，子任务并入主任务阶段。启动只本地归档并记录检查点基线，重试启动、每轮回复、工具和用量事件不触发整理；失败不随无关事务重试。显式上传、删除和用户确认立即按来源版本增量处理。DSH Session 是包含多个 Turn 的会话，不是 Turn 与 Thread 间的额外层级；完整规则见[增量知识规则](incremental-knowledge.md)。
- 复盘经验中的失败反思由插件收集失败/取消/阻塞记录作为证据，经官方 `ctx.llm.stream` 调用和插件专用提示整理提案；不是额外 Skill，也不是宿主原生自动记忆。输出区分失败现象、已有证据、已知原因与待验证假设、改进建议、验证步骤；无证据不臆断，不冒充员工自述，不自动确认事实、修改 Skill 或执行改进。用户明确偏好、来源证据和待验证建议继续区分，分类合并不会改变核验状态。
- 每个知识空间建立 `分类目录/<卡片名>/index.json`，目录名与四张卡片一致。`reference`、`task-evidence`、`incident/reflection-proposal`、`environment/constraint` 为四类稳定 ID；旧需求决策与偏好经验 ID 在上传和读取时归并。索引从有效 A 来源派生，记录来源 ID、版本、标题及 A/原件的相对位置；A/B/C 与原件不因归类改名而重写。迁移只清理可识别的旧派生索引并移除空目录，用户未知文件保留。
- 确认记忆按结构化业务来源归类：项目文件进入专业知识，用户确认及已验收成果进入任务档案。不通过关键词或模型猜测偏好、约束和事实；失败分类只读任务顶层状态，不误用成果正文中的状态文字。
- 资料列表“－”退役当前有效引用；配置来源同时从所属员工的 `modules.knowledge.sources` 移除，并校验员工及来源版本。用户项目文件、历史 A 版本、已发布 B/C 文件与原件保留，退役依据不再用于当前图谱或新编纂。该操作不等于插件完整清理。
- 没有整理成功时如实显示待整理或失败；模型综合继续标记为候选知识。新旧来源并存并可追溯，矛盾待核验，不默认新覆盖旧。结构检查可拒绝名称、类型、版本和引用冲突，不保证完整的语义冲突识别。现有团队资料员整体关闭、来源与版本隔离规则继续生效；整体关闭与单类自动归档开关分别管理。
- 统一减少页头、范围切换、页签、姓名行和表单间距。移除、导入、导出与保存位于员工姓名行右侧，取消底部固定保存栏。

## 实施任务

1. 能力与原生执行：更新 Skill 使用类型、优先能力、原生目录与权限继承；验证兼容旧数据和模型调用边界。
2. 知识后端：四类来源、旧分类兼容、原件上传与列表/阅读/退役接口、同名分类派生索引、个人与团队不同整理提示词；验证原件保留、版本冲突、隔离和失败行为。
3. 知识前端：概念及带谓词的关系图谱、文章及原文阅读、专业知识上传与三类自动归档开关；覆盖模板职业人和项目员工，空白员工提示先保存。
4. 员工与布局：四页配置、顶部保存、紧凑布局和窄屏；连接知识组件与能力组件。
5. 集成验证：类型检查、相关单元与集成测试、构建；用独立官方宿主临时 profile 检查实际深浅主题、窄屏、上传和保存行为。

## 验收

- 配置页只有四个页签，保存后刷新保留必备/优先 Skill、插件与 MCP 偏好；旧工具偏好及历史场景不因布局变更丢失。
- 在认知记忆中搜索定位、拖动和缩放语义图谱；多个连通组同时完整显示，包络不进入语义节点或关系统计。来源、文章、概览不出现在主图或图例，不参与统计、度数和社区；孤立概念不补线。选择概念后一跳邻居高亮，沿概念阅读完整 B 与精确 A 时焦点保留，清空搜索、目录和换库解除旧焦点；目录仍可打开全部文章及概览，旧无图快照文章可读。图谱通过结构、版本与行范围检查，推断明确标记。
- 四类位于图谱上方；“专业知识”的“上传资料”打开原有资料列表，其余三类独立切换自动归档。开关保存后刷新保留；关闭保留旧 A/B/C，开启不立即发起模型。目录与四类同名，旧六类可读可上传且不产生原文版本抖动，退役后历史原件及版本保留。
- 待验收及每轮中间事件不产生自动编纂，任务稳定终点合批且去重；无关事务不重试失败编纂，显式资料操作仍可即时处理。冲突材料保留来源及候选状态，不宣称通过通用语义核验。
- 团队与个人整理的 system prompt 不同，个人知识不自动共享到团队；模板与项目实例归属清楚。
- 姓名行可保存，无底部重复操作栏；缩小布局留白后仍有可操作的控件尺寸和清晰焦点。
- 实现和验证只使用插件自身及官方公开扩展接口；开发验证不宣称新发行包已完成完整交付验收。

## 实施结果

四页设置、原生能力继承、知识上传、认知记忆图谱和专业资料管理均已实现。员工私库使用稳定定位，避免独立员工被团队采用或改换团队时资料失联；原件与 A/B/C 不复制分叉。源码测试和页面验证与安装归档验收分别记录；每份正式归档仍须单独绑定版本、SHA-256 与完整生命周期验收，不能沿用历史归档结论。
