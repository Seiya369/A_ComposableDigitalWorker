# 严格增量知识规则

从 0.5.0 起，增量单位为一份授权来源的版本。新增或更新来源发送该来源当前全文；未变来源仅在支持受影响知识或匹配相关概念时发送已有引用覆盖的原文行。它不承诺对单份变更文档做字符差分，也不以全库重编作为增量失败的兜底。

## 持久基线与计划

每版快照原子记录 `sourceManifest`（来源 ID、版本、内容哈希、核验状态）与知识来源指纹。对比当前有效 A 计算新增、更新、删除；重启不会丢失基线。版本覆盖标题、来源类别和业务元数据变动，归类别名规范化不制造新 A 版本。

旧快照若指纹与当前来源完全一致，可本地补写清单，不调用模型、不增加知识版本。已陈旧的旧快照仅从明确的历史引用恢复已处理版本；未知来源不能假装已被整理。旧概念结构保留兼容，新规则或模型选择变化不会触发隐式全库重编；新变更继续按增量补充知识。

## 失效与必要依赖

更新或撤回 A 后，整项撤销引用失效 A 的 B 文章、概念和关系；再撤销依赖这些 B 的概念、关系和主题摘要，以及失去概念端点的关系。不能只删除引用、文章 ID 或关系端点后保留旧正文和摘要。

混合来源文章或主题仍涉及有效知识时，根据其原有引用收集必要的未变 A 行片段，保留原行号和版本后重新核验。新跨源联系按本地名称、别名、标题索引找相关对象，仅传递命中的概念名称／ID、B 标题／引用和对应 A 片段，不传递整个旧库。名称匹配不能证明语义或因果，模型必须提供具体证据。

单次增量最多 100 个概念锚点、200 个相关文章元数据、300 条已有关系元数据、1,000 个依赖片段；完整模型数据仍受 100,000 UTF-8 字节输入上限约束。已有关系只给出两端均在相关锚点中的 ID、谓词及依据类型，避免模型重发已有关系；delta 不得引用本次未提供的旧对象 ID。超限明确失败并保留旧版，要求拆分变更；不静默裁剪、不重新发送全库。

## 模型边界与合并

需要推理的增量仍使用共享 Wiki 分析提示和 DSH 官方模型服务，两阶段只接收本次增量与必要依赖，共用总时间预算和取消信号。来源和旧候选知识均不构成系统指令。

输出前复核本次有效证据内遗漏的明确关系及有依据的跨资料推断；推断标注依据与不确定性，同页、同源或同主题不构成领域语义关系。该复核沿用本次有限依赖范围，不增加模型阶段或扩大检索，不为图谱连通强制补边、重编历史 A/B/C 或改写未受影响知识；证据不足时保留无边状态。

未受影响的 B/C、概念定义、别名、证据和关系保持原样。模型仅新增或替换受影响对象；新增 ID 使用可复现的增量命名空间，不覆盖未变对象。同名概念经唯一名称／别名映射复用稳定身份，旧定义与原证据保留，仅增加有依据的新文章关联；歧义、类型冲突、自环及重复关系明确失败。新增引用只能落在实际提供的变更来源或依赖片段内。

无差异、重复上传、无差异的重试或“重新整理”不调用模型，也不增加快照版本。独立资料撤回若没有需重编的剩余依赖，则本地移除相关派生对象；最后一份资料撤回会发布空知识快照。跨源综合的撤回不承诺零调用，剩余结论需要重新核验。

## 归档开关与任务阶段

专业知识通过“上传资料”管理。任务档案、复盘经验、工作约束各有独立“开启自动归档”开关；关闭只停止该类后续自动收录和更新，不删除或隐藏已有 A/B/C，也不替代团队资料管理员的整体访问开关。重新开启只恢复后续自动处理，不立即调用模型补扫。

状态事件先做本地来源归档和差异检查，模型编纂按有效验收阶段合批。待验收、工具步骤、用量、运行版本、失败、取消及阻塞不再单独构成付费整理节点；后几类仍保留A档案。验收定稿须与所属任务和最新执行尝试一致；委派子任务随所属主任务验收合批，仅整理本空间可见的成员资料。业务启动使用available模式，只读已有B/C或A元数据，不等待编纂队列。显式资料更新、确认知识与手动整理/重试继续触发严格增量；重复未变输入不重新编纂。

检查点用任务／步骤／主运行身份及稳定状态、最新尝试、成果修订、验收和失效信息去重，不依赖 `updatedAt`、用量或普通版本号。首次启动只归档并记录基线；显式上传、删除、用户确认和授权读取的专业资料变化按增量立即处理。编纂失败保留上一版，只有相关新检查点、实际资料变化或显式重试才重新尝试，无关状态事务不重试失败库。

DSH 的 Session 是持久会话容器，包含多个 Turn，Turn 中可有多个模型与工具 Step；官方没有“介于 Turn 和 Thread 之间的 Session”层级。这里的任务阶段是插件业务检查点，不以每轮回复、agent 空闲或上下文压缩划分。

## 新旧知识冲突

不同来源和历史版本并存，引用可回查；新资料不因日期较新就默认覆盖旧知识。与本次变更相关的旧证据进入有限依赖范围，模型应区分适用范围、版本和不确定性，保留无法消除的矛盾及待确认事项。所有综合仍为候选，来源核验、用户决定与任务验收分别生效。

名称／别名歧义、概念类型、ID、引用版本和范围等结构冲突由确定性校验拒绝；失败保留上一版。当前没有可靠、通用的自然语言语义冲突检测器：名称匹配可能漏掉同义或隐含矛盾，未进入本次依赖范围的旧内容也不会全库重审。提示词要求保留冲突不等于已证明矛盾识别完整。

## 发布、追溯与失败

最终整体结果通过既有引用、名称唯一性、文章覆盖、图谱端点和大小校验。发布在知识根锁内同时比较来源指纹与基线快照版本；任一变化均拒绝晚响应，不覆盖新知识。A 原件和所有旧 B/C 版本保留。

Wiki 阅读投影与语义主图分别派生：`pages` 保留完整 A/B/C 及概念阅读索引，`graph.kind=semantic` 只投影已有概念／实体及有证据的语义关系。同端点关系聚合绘制但保留每条方向和谓词；关系条数决定权重和节点度数。增加阅读页面不增加主图点、边或度数，社区只按语义图计算。旧无概念图快照显示空图并保留文章阅读；重建这一派生视图不修改 A/B/C、不调用模型，也不制造知识更新。

二维分组总览、一跳邻居高亮和搜索定位均在浏览器处理。连通组包络和组间排布只表达视觉位置，不向知识快照追加桥接关系，也不触发资料增量或模型编纂。阅读概念对应文章与来源证据保持图谱焦点；这些交互不会发布新知识版本。

每次发布的 `compilationTrace` 记录本次增量规则、实际模型路由、变更／撤回来源及模型调用次数，并归档到准确版本。每次编纂尝试另有不可变账本，记录发布、失败、取消或被新版本取代；知识界面最多显示最近50项。模型若返回官方 usage，记录未命中输入、缓存读写、输出及可用推理计数；缺失字段不推算成零，部分已报告用量仅为下限。取消后服务商迟到或未提供的账单无法补造。升级时保存旧manifest中仍可恢复的当前trace，更早已丢失统计保持未知。账本不进入模型上下文，不把旧保留文章误记为由新模型生成。

## 四类来源

| 名称 | 内容与边界 |
| --- | --- |
| 专业知识 | 专业资料与授权项目文件，通过“上传资料”打开上传／查看／移除列表 |
| 任务档案 | 需求、决策、纠正、任务过程、成果与验收依据；独立自动归档开关 |
| 复盘经验 | 失败记录、待验证复盘、明确偏好和能力证据；独立自动归档开关 |
| 工作约束 | 环境、规则、授权边界和条件；独立自动归档开关 |

旧需求决策归入任务档案，旧偏好经验归入复盘经验，旧环境约束改显示工作约束。分类不是确认事实或能力的依据；失败原因假设不得标为事实，改进建议不得标为已经执行，也不会自动修改 Skill。

只有已知的业务来源或明确类别决定归档，不通过正文里出现“失败”“偏好”等词猜类别。确认记忆按其业务出处归入任务档案或专业知识；用户明确确认属于显式处理，不由自动开关代替确认。目录是四类有效 A 的派生索引，与界面同名；旧 A/B/C 不重写，旧派生目录中的未知文件与链接保留。
