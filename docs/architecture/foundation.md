# 可组装数字员工基座

> **0.4.0 在官方全局面板内增加项目工作台。** 约束见[官方插件边界](../decisions/001-official-plugin-boundary.md)，模板、实例与 JSON 交换关系见 [graph_horses 契约](graph-horses.md)。历史自加工作区插槽已从插件接入中移除。

本基座为 DeepSeek Harness 0.2.1-alpha.2 的独立 Host + Client 插件，通过官方公开服务和客户端插槽接入，不要求修改宿主。员工执行复用 Harness 原生 Agent、模型、会话和工作区服务。插件独立构建和分发，运行时共享宿主进程与页面。

新版宿主的分层职责和接口差异见 [Harness 0.2.1 架构说明](../../integration/architecture-0.2.1.md)。

## 用户入口与分层

```mermaid
flowchart TB
  A[全局 graph_horses 面板] --> D[职业人、团队和工作流模板库]
  B[graph_horses 项目实例 / 会话团队按钮] --> E[项目员工实例]
  C[项目对话：@ 员工] --> F[任务入口]
  D -->|指定版本快照| E
  E --> F
  F --> G[运行调度：排队、预算、授权委派]
  G --> H[Harness 原生 Agent / 模型 / Session]
  H --> I[授权文件、记忆与交付工具]
  I --> J[待验收成果]
  J --> K[验收记录与有来源的记忆]
```

`src/domain` 管理七模块配置、模板、团队、项目实例、记忆和工作单。`src/work` 管理项目目标、稳定任务、成果修订、依赖图、人工验收和受控并行调度。`src/workflow` 保留原有顺序流程定义、运行状态、步骤派发和验收交接。`src/harness` 负责原生服务接入、员工执行和实际工具调用。`src/client` 提供宿主 UI 入口及输入路由。`src/ui` 提供独立的中文配置组件。

客户端通过官方 `sidebar.panellist` 与 keyed `main` 注册全局入口，通过 `shell.overlay`、会话输入和 `@` 来源提供项目快捷操作。包的安装和移除由官方 profile 管理，普通卸载保留数据，完整清理按归属删除专属状态和配置。安装包切换后需重启宿主并刷新页面。

## 身份与组织关系

- 模板描述可复用岗位，不包含任何项目记忆。新模板默认为空白草稿。
- 团队模板组合员工模板，并以本地成员 ID 表示汇报关系；实例化时一次复制成员与关系。
- 项目绑定 Harness 稳定 Workspace ID，路径与名称只作为属性。
- 项目员工有自己的稳定 ID 和七模块快照。修改模板不会自动覆盖既有项目配置。
- 员工的汇报关系用于组织结构；可委派范围由实际团队关系与非空显式目标列表共同确定。头衔本身不授予工具或指挥权限。
- 每次工作单产生独立原生会话。员工身份、任务 ID 和会话 ID 分别管理。

项目实例通过“引入通用模板”选择一个平台团队，在一次事务中创建全部员工实例、汇报关系和工作流副本。项目与来源团队组合唯一，重复提交返回原安装；团队和员工模板版本不匹配时拒绝首次安装。已有实例只在岗位唯一、关系明确时纳入团队，保留其权限、岗位配置和记忆，不复制其他项目的数据。详情见下方“项目团队配置”。

## 员工设置与当前执行能力

员工只显示岗位定义、模型配置、能力组合、认知记忆四页，历史七模块数据保留兼容。模型可手选或跟随 DSH 默认值；必备 Skill 每份工作单载入，优先 Skill 和工具按适用场景优先使用。其他原生可用 Skill 和工具仍可调用。

从原生对话创建的工作单继承来源会话预设与权限模式，独立任务使用宿主默认预设；原生文件、终端、网络与第三方工具的执行约束由 DSH 及工具本身负责。插件继续管理项目任务、记忆范围、成果版本、取消和预算，不再维护员工文件/Shell/网络 ACL。详见[官方能力接入](native-capabilities.md)。

## 项目记忆

记忆分为项目共享与项目内员工专属两种范围，均记录来源、核验时间和版本。任务只注入并查询当前授权范围的记忆，其他项目的内容不会随同名模板流入。长期记忆由用户确认，或引用已经验收且归属正确的交付物；未经确认的模型结论不自动记为事实。

当前项目已录入用户明确提出的产品目标，作为架构师可以读取的初始项目共享记忆。项目临时状态、运行日志和知识记录分开保存。

团队显示默认勾选的资料管理员，模板与项目实例可独立关闭，控制团队及员工跨任务知识的整理和使用；已有知识、任务与原生会话保留。它维护三级知识：A 保存原始文本、规范阅读版和来源版本，B 保存引用 A 的详细重组知识，C 保存引用 B 的概念、实体和综述。模板和项目团队实例的团队共享库、员工专属库分别隔离；项目运行知识不反向流入模板。团队管理员使用官方 LLM 服务、跟随唯一负责人的有效模型；员工私库使用员工模型和独立的影子整理提示词，不创建可派工员工或原生会话。工作 agent 在具备记忆工具和相应范围授权时默认注入 C，并按需读取 B/A。生成综合保持候选状态，不改变长期确认记忆与任务验收规则。详见[团队知识库](team-knowledge.md)。

认知记忆主区通过共享 Wiki 程序展示概念／实体语义图：点仅为概念或实体，边仅为有证据的语义关系，孤立概念不按共享文章或来源补线。C 概览、完整 B 与 A 来源保留在阅读目录，点击概念可读文章并回查原文；旧无图快照不影响文章访问。上方保留专业知识、任务档案、复盘经验、工作约束四类短卡；专业知识提供“上传资料”，其余三类独立切换“开启自动归档”。关闭自动归档保留已有 A/B/C，开启不立即调用模型补扫；自动编纂按任务稳定阶段合批。四类名称同时用于各知识空间的 `分类目录/` 子目录，其 `index.json` 为有效来源的派生索引。移除只退役当前引用并同步配置来源，历史 A、B/C 与原件留存，不删除用户项目文件。详见[认知记忆改造](employee-settings-refresh.md)。

## 调度与交付

同一员工串行处理任务，不同员工可以并行。向其他员工委派必须满足当前项目、允许对象、层级、并发与总预算限制；循环指挥和互相等待在入口处拒绝。全新 profile 的种子提供产品、架构、设计、开发、测试和运维六岗位及两条完整软件工程工作流；安装不执行任务，委派只使用当前项目真实名册及原生授权。已有 profile 不静默覆盖用户定义。

每次运行保留配置快照和开始时继承的原生权限。项目知识范围、员工状态和任务有效性继续检查当前状态；来源会话后来切换模式不会实时改变已有工作单。取消排队任务即时更新状态，取消执行任务向原生模型请求传播中断。

工具产物记录真实路径；原生 `write/edit/present` 的项目内成果保留有界文本快照。文件授权沿用 DSH 原生机制。正常执行结束进入待验收，真人可验收或退回。宿主重启保留工作单及原生历史，不自动重放未完成操作。

项目工作台另以稳定任务身份关联每次工作单尝试，管理目标、前置任务及必交成果。项目显式启动后，在项目和全局并发预算内调度依赖就绪任务；前置任务及当前成果必须验收后才能交接。成果修订保留旧版本和验收历史，使受影响后继需要重新验证；重试只新增该任务的尝试。只有项目必交成果的当前有效版本均通过验收且无未完成任务时才允许确认完成。重启暂停项目自动派工，原有顺序工作流可复制成独立任务计划。界面与状态契约见[项目工作台](project-workbench.md)。

## 持久化与宿主兼容

首版采用带版本检查与原子写入的 JSON 存储，适合一个本地 Harness 服务、多浏览器窗口使用。正式安装的专属数据默认位于 `$DSH_HOME/composable-workforce/state.json`，已有本地演示 profile 可继续使用其已配置的 `.local/workforce.json`。原生会话由 Harness profile 管理。密钥继续由 Harness 原有凭据服务提供，插件配置不保存密钥。

官方全局面板和会话插槽已足够提供当前入口。构建时不复制或替换宿主组件，归档不含历史源码补丁；兼容预检只验证目标发行版及所用公开接口，完整生命周期另行验收，详见 `integration/README.md`。

## 后续扩展顺序

1. 按同一七模块模型添加产品、开发、测试员工，为团队配置真实委派授权。
2. 为项目外部操作完善任务取消和真实交付记录，保持官方工具与审批机制。
3. 通过真实项目检验任务与成果模型，再按需要增加条件分支、自动规划及更复杂的协作流程。
4. 根据真实团队任务量，再引入数据库及分布式调度。

后续能力应沿现有接口逐步增加，并通过实际执行验证；当前界面中预留的数据字段不等于已具备对应执行器。

## 项目团队配置

项目入口为“配置团队”，一次单选一个团队。`project.team.configure` 将员工和工作流在一个事务内保存为 `ProjectTeam`，并将团队成员 ID 映射为本项目员工 ID。员工岗位模块、工作流步骤均是独立快照。项目工作流可显式发起，由插件顺序调度器通过 `WorkflowExecutor` 接口复用现有员工执行器；每步人工验收后继续，支持暂停恢复、取消和有上限的人工重试。配置团队不会自动运行流程。

`projectTeams` 与 `TeamTemplate.workflows` 是可选字段，旧数据以未配置团队和空工作流读取。项目与来源团队组合唯一，重复提交返回原安装，版本改变不覆盖项目副本。可明确匹配的旧项目员工纳入团队时保留身份、权限、岗位配置和记忆；新员工的私有记忆为空，草稿岗位创建为暂停状态。已归属项目团队的员工不能删除，使用暂停保留流程引用。平台团队的删除不会删除项目团队副本。

存在有效配置时，可在 graph_horses 的项目实例配置中查看团队或取消团队。`project.team.cancel` 接收项目 ID 及明确的安装 ID、版本列表，在同一事务中标记取消、停用成员、结束未完成的流程与待执行工作；提交后由员工执行器中止进行中的任务及子任务。取消保留员工、流程配置、产物和记忆，迟到的执行结果仍以已取消状态收录。旧安装没有 `status/version` 时按 active/1 读取。取消后的团队从工作名册隐藏，禁止单独重新启用成员；重新选择同一团队时，`project.team.configure` 需携带取消记录的 `restoreVersion`，恢复原实例及取消前的启用状态。旧配置请求不能意外恢复团队，旧取消请求不能取消已恢复的团队。恢复不会重跑历史工作。

工作流运行记录使用可选 `workflowRuns` 字段，旧数据无需迁移；每次运行保留定义快照、步骤尝试、幂等命令和事件记录。执行策略与持久化恢复边界见[顺序工作流执行契约](workflows.md)。
