# 可组装数字员工基座

本基座为 DeepSeek Harness 0.1.1-rc.2 的独立 Host + Client 插件，当前适配提交 `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e` 加本项目的[通用工作区扩展补丁](../../integration/README.md)。员工执行复用 Harness 原生 Agent、模型、会话和工作区服务。插件独立构建和分发，运行时共享宿主进程与页面。

## 用户入口与分层

```mermaid
flowchart TB
  A[工作区：数字员工模板入口] --> D[模板与团队库]
  B[项目菜单：配置团队] --> E[项目员工实例]
  C[项目对话：@ 员工] --> F[任务入口]
  D -->|指定版本快照| E
  E --> F
  F --> G[运行调度：排队、预算、授权委派]
  G --> H[Harness 原生 Agent / 模型 / Session]
  H --> I[授权文件、记忆与交付工具]
  I --> J[待验收成果]
  J --> K[验收记录与有来源的记忆]
```

`src/domain` 管理七模块配置、模板、团队、项目实例、记忆和工作单。`src/workflow` 管理流程定义、运行状态、步骤派发和验收交接。`src/harness` 负责原生服务接入、员工执行和实际工具调用。`src/client` 提供宿主 UI 入口及输入路由。`src/ui` 提供独立的中文配置组件。

宿主只提供通用的标题栏和工作区菜单插槽；插件通过 `ctx.slots.inject/register` 添加入口，不再复制或禁用原生工作区组件。包的安装和移除由 Harness profile 管理，卸载清除功能入口，独立数据文件保留。安装包切换后需重启宿主并刷新页面。

## 身份与组织关系

- 模板描述可复用岗位，不包含任何项目记忆。新模板默认为空白草稿。
- 团队模板组合员工模板，并以本地成员 ID 表示汇报关系；实例化时一次复制成员与关系。
- 项目绑定 Harness 稳定 Workspace ID，路径与名称只作为属性。
- 项目员工有自己的稳定 ID 和七模块快照。修改模板不会自动覆盖既有项目配置。
- 员工的汇报关系用于组织结构；可委派范围另由明确的模板授权列表控制。头衔本身不授予工具或指挥权限。
- 每次工作单产生独立原生会话。员工身份、任务 ID 和会话 ID 分别管理。

项目文件夹通过“配置团队”单选一个平台团队，在一次事务中创建全部员工实例、汇报关系和工作流副本。项目与来源团队组合唯一，重复提交返回原安装；团队和员工模板版本不匹配时拒绝首次安装。已有实例只在岗位唯一、关系明确时纳入团队，保留其权限、岗位配置和记忆，不复制其他项目的数据。详情见下方“项目团队配置”。

## 七模块与当前执行能力

架构师种子配置见 `src/domain/seed.ts`。职责、技能正文、知识来源、已确认记忆、协作规则和交付要求组合成原生 Agent 的系统指令；模型配置直接选择实际 Harness 模型。

当前内置技能为架构分析、架构设计和技术评审，正文保存在 `skills/*/SKILL.md`。当前工具集合为文件列表、读取文件、新建交付物、查询记忆、保存已验收成果记忆和委派。员工仅得到“能力组合”与“权限”共同允许的工具；架构师默认未开启写记忆工具。

工具注册和运行权限检查是今后添加连接器的扩展位置。填写陌生技能或工具 ID 不会安装能力。首版未提供 shell、网络抓取和外部应用执行适配器；网页来源保存引用，不自动加载网页正文。

## 项目记忆

记忆分为项目共享与项目内员工专属两种范围，均记录来源、核验时间和版本。任务只注入并查询当前授权范围的记忆，其他项目的内容不会随同名模板流入。长期记忆由用户确认，或引用已经验收且归属正确的交付物；未经确认的模型结论不自动记为事实。

当前项目已录入用户明确提出的产品目标，作为架构师可以读取的初始项目共享记忆。项目临时状态、运行日志和知识记录分开保存。

## 调度与交付

同一员工串行处理任务，不同员工可以并行。向其他员工委派必须满足当前项目、允许对象、层级、并发与总预算限制；循环指挥和互相等待在入口处拒绝。种子模板默认只有架构师，委派名单初始为空；在项目中配置实际同事和授权后才可委派。

每次运行保留配置快照，权限执行同时受快照与当前授权限制。开始后撤销授权不会被旧配置绕过。取消排队任务即时更新状态，取消执行任务向原生模型请求传播中断。

工具产物记录真实路径。默认只允许在 `docs/architecture/**` 新建文件，已有文件不会被覆盖；修订时提交新的版本文件。正常执行结束进入待验收，真人可验收或退回。宿主重启保留工作单及原生历史，不自动重放未完成操作。

## 持久化与宿主兼容

首版采用带版本检查与原子写入的 JSON 存储，适合一个本地 Harness 服务、多浏览器窗口使用。运行数据默认位于 `.local/workforce.json`，原生会话位于独立 `.local/harness` profile。密钥继续由 Harness 原有凭据服务提供，插件配置不保存密钥。

宿主通过配套通用补丁提供工作区工具栏和项目菜单插槽，插件通过公开 Client 接口追加入口，构建时不复制或替换工作区组件。未应用插槽补丁的原版宿主暂不支持这些入口，详情见 `integration/README.md`。

## 后续扩展顺序

1. 按同一七模块模型添加产品、开发、测试员工，为团队配置真实委派授权。
2. 增加技能与工具能力目录，让配置页面直接选择已安装且可执行的能力。
3. 为外部应用接入独立适配器，同时实现授权检查、超时、取消和真实交付记录。
4. 根据真实团队任务量，再引入数据库、任务恢复策略与更复杂的协作流程。

后续能力应沿现有接口逐步增加，并通过实际执行验证；当前界面中预留的数据字段不等于已具备对应执行器。

## 项目团队配置

项目入口为“配置团队”，一次单选一个团队。`project.team.configure` 将员工和工作流在一个事务内保存为 `ProjectTeam`，并将团队成员 ID 映射为本项目员工 ID。员工岗位模块、工作流步骤均是独立快照。项目工作流可显式发起，由插件顺序调度器通过 `WorkflowExecutor` 接口复用现有员工执行器；每步人工验收后继续，支持暂停恢复、取消和有上限的人工重试。配置团队不会自动运行流程。

`projectTeams` 与 `TeamTemplate.workflows` 是可选字段，旧数据以未配置团队和空工作流读取。项目与来源团队组合唯一，重复提交返回原安装，版本改变不覆盖项目副本。可明确匹配的旧项目员工纳入团队时保留身份、权限、岗位配置和记忆；新员工的私有记忆为空，草稿岗位创建为暂停状态。已归属项目团队的员工不能删除，使用暂停保留流程引用。平台团队的删除不会删除项目团队副本。

存在有效配置时，原生项目菜单显示“查看团队 / 取消团队”。`project.team.cancel` 接收项目 ID 及明确的安装 ID、版本列表，在同一事务中标记取消、停用成员、结束未完成的流程与待执行工作；提交后由员工执行器中止进行中的任务及子任务。取消保留员工、流程配置、产物和记忆，迟到的执行结果仍以已取消状态收录。旧安装没有 `status/version` 时按 active/1 读取。取消后的团队从工作名册隐藏，禁止单独重新启用成员；重新选择同一团队时，`project.team.configure` 需携带取消记录的 `restoreVersion`，恢复原实例及取消前的启用状态。旧配置请求不能意外恢复团队，旧取消请求不能取消已恢复的团队。恢复不会重跑历史工作。

工作流运行记录使用可选 `workflowRuns` 字段，旧数据无需迁移；每次运行保留定义快照、步骤尝试、幂等命令和事件记录。执行策略与持久化恢复边界见[顺序工作流执行契约](workflows.md)。
