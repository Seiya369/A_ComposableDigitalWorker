# 模板库列表排序

自由职业人库、团队、工作流的左侧根列表支持按住鼠标上下拖拽。指针移动超过 5 像素后进入拖拽状态，目标行上半部表示放到前面，下半部表示放到后面，并显示落点线。拖拽结束不会误触发行选择或团队展开。释放到列表以外、放回自身或按 Escape 取消均不保存；拖拽中的 Escape 只取消排序，不继续关闭外层弹框。

聚焦列表行后可按 `Alt + ↑`、`Alt + ↓` 进行相同的排序操作，完成后焦点保留在原记录。位于边界时不发送请求。排序不依赖员工名称，始终使用稳定 ID。

## 持久化与并发

客户端调用 `library.reorder`：

```json
{
  "action": "library.reorder",
  "payload": { "kind": "employee", "orderedIds": ["id-b", "id-a"] },
  "options": { "expectedRevision": 123 }
}
```

`kind` 为 `employee`、`team` 或 `workflow`。`orderedIds` 必须完整覆盖对应库当前可排序记录，不能包含重复、缺失、跨库或已归档员工的 ID。`expectedRevision` 必须为当前工作区版本；不匹配时返回冲突，客户端显示错误并重新读取，不覆盖其他窗口的修改。重试须基于刷新后的顺序。

服务端在同一次带锁事务中验证并原子写入现有数组，工作区 revision 递增。实体 ID、版本号、内容、时间戳及项目中的独立副本保持不变；不新增状态模式或单独排序数据库。刷新和重新启动后从数组恢复顺序。

## 过滤、归档与组织结构

有搜索筛选时，只在匹配项原本占据的槽位之间重排。例：`A、隐藏项、B` 筛选出 `A、B`，拖动 B 到 A 前面后为 `B、隐藏项、A`。未匹配项的位置和内容不变。员工库仅排序未归档模板，已归档项在完整数组中的位置与对象保持不变。

团队页只拖拽团队根行；成员组织树继续只读，不支持点击或拖拽成员。移动团队时成员顺序、上下级关系和整个子树保持原样。根列表排序也不改变工作流内部步骤顺序或项目人员关系。

## 与编辑草稿分离

列表顺序即时独立保存，不提交、清空或放弃右侧未保存的员工、团队或工作流草稿。排序期间阻止重复提交并标识忙碌状态；冲突或读取失败显示错误，保留草稿。切换到其他记录时仍使用原有未保存确认流程。

域与 HTTP 回归见 `tests/library-order.test.ts`、`tests/transfer-api.test.ts`。实际鼠标、键盘、过滤、取消、并发和草稿回归位于 `tests/ui/library-order.checks.mjs`，由官方临时 profile 的工作流 UI runner 使用 `WORKFORCE_LIBRARY_ORDER_VALIDATION=1` 启用。
