# 项目对话工作流

## 目标与确定的规则

以原生项目对话作为工作入口，底部用“工作流”上拉菜单替代旧“团队”配置弹框。菜单首项为“无”，未配置时明确显示“工作流：无”，选择后显示“工作流：名称”。项目首次选择非空工作流时，清除该项目此前的对话空覆盖，使所有对话统一使用此项目默认；之后在某一对话切换其他工作流或“无”仅影响该对话。同一项目、同一工作流共享步骤进度。

选择全局工作流时原子创建独立项目团队、人员、组织关系和冻结流程副本，不接管旧项目团队，不静默覆盖已有任务或成果。相同项目和来源工作流再次选择复用该副本。全局模板后续变化不改写已安装版本。

持久化使用可选 `state.conversationWorkflows`（`instances`、`defaults`、`selections`），旧状态无需迁移或自动执行。实例以项目和来源工作流 ID 唯一，保存来源工作流/团队版本及专用项目团队/流程 ID。项目团队使用 `conversation-workflow:<来源工作流 ID>` 作为独立安装来源，保留原来源团队 ID 作为溯源，不接管之前独立引入的团队。首次选择“无”只保存临时的对话空覆盖，不建立项目默认；项目首次非空选择时统一清除这些前置覆盖。已经存在项目默认时，后续“无”作为本对话独立覆盖保留。升级不静默清除已有项目默认、人工选择、步骤或验收记录。来源模板被移除后，项目冻结副本及历史仍保留且可选择。

新引入的团队快照保存资料管理员开关，项目安装优先使用这一冻结值。旧快照缺失该字段时，仅在同 ID、同版本的来源团队仍存在时读取它当时的开关；来源已更新或移除则默认关闭，避免因旧格式缺信息而意外开启长期资料归档与读取。之后修改源团队不会改变项目副本的开关。

步骤显示灰色未完成、白色已验收、蓝色当前步骤。蓝色采用原生对话标签的业务主色。点击只选择当前步骤，不把之前步骤标为完成；完成依据本步骤负责人真实交付的人工验收记录。返工保留历史并撤销受影响步骤的当前有效性。执行中的对话不允许切换身份，先等待当前 turn 结束或按原生停止。

步骤进度属于项目工作流实例；同一项目内继承或选择同一工作流的对话读取同一当前步骤。当前步骤优先显示蓝色，即使它以前验收过；点选不会撤销或伪造验收。只有当前步骤主负责人根工作单的人工验收可以推进，普通 turn 结束、模型自述完成、子任务验收均不能推进。验收必须有实际交付文本或产物引用；正在执行的根/子工作单未结束时不能切换共享步骤或验收推进。接受后寻找下一未验收步骤，若前面仍有跳过的步骤则回到它，全部验收后不再有当前负责人。拒绝时按 `onRejectStepId` 返回指定步骤（未配置则留在本步），为返回步骤及后续已验收记录添加失效时间与原因，原交付及人工验收历史保留。

用户普通输入在同一个原生 Agent 中由当前步骤负责人处理，无需 @；保留用户消息、附件、历史、停止、模型重试和原生审批语义。不另开负责人对话，不重复发送。负责人遵守岗位配置与步骤说明、交付要求、验收标准，可规划任务、委派下级，必要时明确说明原因并咨询同项目其他步骤负责人。规划不自动授予生产发布等权限；所有动作继续服从原生沙箱和审批。

## 官方扩展边界与位置降级

基线为 DSH 0.2.1-alpha.2。使用公开 `conversation.input.left`、`conversation.session.header.utilities`、Agent 的 prompt assembly/request/turn 生命周期、工具注册与单调 guard，不修改宿主或替换原生组件。

当前官方没有跨越标题和标签两行的附加区域。0.21 起步骤条使用右对齐的 `header.utilities`，顺序在原生打开方式下拉之前，保留原生标题、其他 actions 及对话/轨迹。通过自身响应宽度扩展显示空间；右侧与原生打开方式控件外界按当前官方 8px gap 加自身 28px 间距得到 36px。左边界不能与下一行“轨迹”精确绑定；高度变化只自然撑开自身宿主行，不越界覆盖原生内容。这是明确降级，不冒称红框位置完全一致。

原生 prompt 先 assembly 后 pre-step，因此在首次 assembly 冻结本 turn 的选择、负责人和模型，加载必备技能与知识入口；pre-step 与工具调用继续检查权限和绑定。身份作为 required runtime context，不覆盖完整原生 preset。工作流选择为“无”时不再注入负责人身份/模型/业务工具。

“无”恢复 DSH 自身的模型选择规则：用户明确选择的原生模型优先，否则沿用原生 `lastUsed`。上一轮实际由员工模型完成时，它可能仍是原生最近使用的模型；这只表示原生模型选择，不保留员工身份或业务工具。插件不为了“无”回滚初始模型，也不隐式改写全局模型默认。

## 结构与实施顺序

1. `src/domain/conversation-workflow.ts`：持久默认、会话覆盖、冻结安装、当前步骤、有效完成记录及协作名册；`store` 负责原子事务和 CAS。
2. `src/harness/conversation-workflow-runtime.ts`：公开原生 Agent 生命周期适配；业务 lease 由 WorkforceRuntime 提供，复用已存在的权限、知识和委派逻辑。
3. `src/client/conversation-workflow.ts`、`src/ui/ConversationWorkflow.tsx`：共享控制器、上拉列表和顶部步骤条；host 从官方工作区归属解析项目，禁止客户端伪造跨项目对话。
4. 删除被替代的 ProjectTeamDialog 和 client configure-team 路由；保留历史数据读取与仍被新功能复用的业务服务。
5. 类型检查、域/HTTP/Agent 生命周期测试、真实浏览器检查、归档白名单和独立官方 profile 安装生命周期验收。

不因本次代码清理删除用户会话、知识、交付、待验收任务或共享凭据。卸载先取消插件当前 lease，再移除监听、工具、上下文、UI 和定时器；不销毁宿主原生 Agent。

GET `/digital-workers/api/conversation-workflow?sessionId=...` 返回该原生对话的有效选择、候选工作流、当前负责人及下属协作名单、各步骤状态和存储 revision。未绑定项目的对话返回空候选与 `projectId: null`。选择和切换步骤经既有命令路由的 `conversation.workflow.select` / `conversation.workflow.step` 提交，必须携带当前 `expectedRevision`；步骤额外检查实例版本。host 从官方工作区注册表核验真实 session/project 归属；域层再次核验持久实例、人员及流程归属。普通派工只可发给当前步骤负责人，子任务自动继承冻结流程链接，必要咨询的限制由运行时进一步检查，链接本身不构成工具或权限授权。

“无”只解除工作流的负责人上下文、业务工具和模型覆盖，沿用 DSH 原生模型选择规则（包括最近使用的模型）。它不重置原生模型、不修改全局默认；用户在原生选择器明确改选后仍按原生选择工作。历史会话中的先前岗位与知识记录继续保留，不把“无”解释为清空对话历史。

## 旧独立员工对话的兼容

0.18.1 起，无 parentRunId、conversationWorkflow、workflow 或 workTaskId 的旧独立根工作单，在停止执行后不再阻止原会话使用工作流；没有显式覆盖时也继承项目默认。旧工作单仍是历史记录，不因界面迁移变成已验收或被取消。底部仅隐藏这类旧静止状态，不隐藏新工作流交付、执行中任务和有关联任务的待验收入口。

若该会话的已停止 Agent 仍由本插件持有，GET 投影仅返回 sessionHandoffRequired，不进行读操作副作用。客户端通过 conversation.workflow.resume 握手，校验项目归属及空闲状态后，完整释放插件拥有的旧 AgentHandle，再使用公开 SessionController.resolveAgent 恢复相同 Session ID；原生预设、权限和日志按官方服务恢复。不更改会话 selection，不把继承改为 override，也不调用模型。忙碌、待处理消息、子任务、工作流或任务工作台会话不能这样交接。

官方 alpha.2 客户端会将已移除 Agent 的保留 Session generation 标为 removed，同 ID 的 openSession 不能重置它。交接成功后，仅在用户仍停留于原会话且公开导航 ticket 有效时，以公开 openSession 保留身份并标准刷新页面，释放失效的客户端 generation；原生持久化草稿随同 ID 恢复。不读取或改写宿主私有 store，也不销毁原生 UI 持有的引用。未发送附件不受原生草稿持久化保护，因此有附件或正在提交时禁止自动刷新，显示明确恢复提示，待处理附件后再由用户继续。离开页面、切换会话或插件已卸载时不拉回、不刷新。

历史版本给宿主自有 Agent 安装的旧只读限制随 DSH 重启清除；不尝试冒领或销毁宿主 Agent。极旧日志若引用已不存在的预设，报告官方恢复失败、保留日志并允许重试，不篡改 header 或静默换预设。

## 0.19 圆点条与精简详情

步骤状态使用灰/白/蓝填充圆点，名称在下方，溢出省略且详情按钮固定可见；当前步骤在窄屏省略窗口中仍可见。保留官方标题旁插槽，不重排原生标题和对话/轨迹。旧项目工作区入口及整套页面已删除，主面板只留三类资源库。

详情是插件自有对话框，通过 session 归属过滤的白名单 DTO 展示冻结要求、负责人及下级、最新交付，任务摘要和交付历史折叠。查看步骤不激活，明确设置才改变当前步骤。现代根交付统一走专用安全验收入口，通用 run.review/run.cancel 禁止处理对话工作流，避免绕过原生会话及完整版本检查；选择“无”后的记录保留并提示先选择所属流程。具体入口与历史交付兼容见 [工作流详情与交付验收](project-delivery-review.md)。

## 0.21 顶部区域与真实退回连线

节点所在区域移入公开右侧 utilities，宽屏扩展且保留原生标题、模式及右侧控件；窄屏保留省略窗口和详情入口。顺序线来自冻结步骤数组，显式 `onRejectStepId` 自0.21.3起使用步骤名称下方的虚线箭头/自回环，不把布局线当作执行条件。最多三层轨道按区间复用，未显示端点或拥挤的线不绘制，按钮无障碍描述及详情仍提供真实退回目标。所有坐标与裁剪均限于插件子树，不移动或样式化宿主祖先。0.21.1 起节点采用28px双圈，中心按冻结步骤的全局顺序显示1、2、3等序号；两层圆均按官方主题的 Full-round 约定显式设置 `corner-shape: round`，避免全局 superellipse 将50%圆角变成方形；数字使用官方静态黑色保证灰、白、蓝填充在深浅主题下可读，名称保留原有12px字号。顶部高度无退回线52px，按可绘轨道增至61/68/75px；连线端点仍贴合节点圆周。

## 0.21.2 居中步骤窗口

显示不全时，当前步骤从中间槽位之后推动可见窗口向左移动；七个可见节点时第1至4步位置固定，第5步起选中节点位于第4槽。窗口抵达末尾后固定，选择末尾的其余步骤不会再移动节点；反向选择前面的步骤按同一规则恢复窗口。其他宽度按实际可见数量选择中间槽位，偶数时使用左侧中间槽。两侧各预留24px省略入口，即使暂时没有隐藏步骤也保留空位，防止省略号出现或消失时重新分配节点坐标；只在有隐藏步骤的一侧显示“…”并打开详情。步骤全部能放下时不预留省略入口。区域小于76px、放不下一枚28px节点及两个省略入口时，只保留当前节点，通过外部“详情”查看其他步骤；不缩小圆点。窗口只改变展示，不改变步骤状态、顺序、验收记录或当前负责人选择规则。

## 0.21.3 下方回退路径

只改变回退路径的绘制，不重新分配原有行高、节点/名称坐标或原生标题/标签位置。`height`、`reserveTop`、`nodeY` 与0.21.2同一窗口保持一致；独立 `drawingHeight` 允许自身绝对定位SVG向下延伸最多23px。顺序线保持原样；回退线从圆的右下45°点进入文字外侧沟槽，绕过步骤名称，在名称下方最多三层轨道连接到目标圆左下45°点；自身返工同样绕过自己的名称。

组件只读最近的语义 `header` 边界和其他原生交互控件的矩形，测量下方安全空白，不写宿主DOM或祖先样式。SVG自身裁剪横向边界、使用 `pointer-events:none`；监听自身/头部尺寸及文字变化，卸载时断开。没有标签行或极窄宽度使下方空间不足时，完整隐藏放不下的路径并在“详情”保留目标，不裁断箭头、不覆盖标签或正文。未测量前只画顺序线。此测量是插件内部布局防护，不是新增宿主接口。

## 2026-10-25 顶部与详情的整理

本节取代0.21.2中省略按钮以及0.21.3中下方退回线的当前行为；历史记录保留用于溯源。

顶部仍使用官方 `conversation.session.header.utilities`，保留52/61/68/75px原有占位与横向窗口。节点、名称、普通顺序线和静态省略提示作为一个整体，在实测安全空白内向下平移最多12px；详情按钮、原生标题、工具、tabs与正文位置不随此移动。退回线恢复上方轨道，端点接真实圆周，不经过名称。初始/不足空间时缩小平移量而不撑高宿主，实际值记录在插件nav的 `data-offset-y`。只读观察器卸载时断开，不写宿主DOM或祖先样式。

两侧“…”只表示隐藏步骤，不可点击且不进入焦点。首尾可见节点外有冻结定义中真实相邻步骤时，增加最多12px短顺序线；空间小到无可用长度时不画。不会把退回箭头接到省略符，也不会跨越中间被隐藏的步骤制造顺序边。完整流程统一经“详情”浏览。

详情默认只回答三个问题：执行到哪一步、该步交付了什么、是否验收以及意见是什么。左侧是完整竖向步骤、状态与负责人；右侧是所选步骤、阶段文件、交付状态、时间及验收信息。点左侧只读取步骤，显式“设为当前”才更改负责人；执行中与版本校验继续生效。步骤要求/退回规则、任务分解、交付历史和模型回复按需展开；待验收时保留通过/退回和退回必填原因。窄屏把竖向步骤放到内容上方的可滚动区域。

有效成果严格来自当前项目冻结实例的未失效 `completion.runId`，并核验项目、步骤、主负责人、成功状态、验收决定和时间。已完成步骤的新失败尝试不覆盖该有效成果；当前步骤优先显示最新尝试，保证新的待验收交付可见；历史浏览优先显示明确选择的run。返工使完成记录失效后不再将旧成果作为有效版本，原记录仍可在历史查看。阶段文件展示真实run中保存的快照、项目相对路径及明确的预览缺失/截断状态，不把当前磁盘文件冒充历史，也不把任意路径变成未经验证的打开/下载入口。保留“打开原对话”作为原生回溯入口。

项目Wiki有独立价值：将跨步骤反复使用的需求、决策、术语与依据整理成可检索知识；步骤文件和人工验收仍是交付事实的依据。入口固定放在详情顶部，在同一对话框中切换，返回后保留步骤和未提交验收说明。它复用该冻结项目团队的共享知识空间，与步骤选择无关；不是每一步单建知识库，也不混入全局团队模板或个人知识。团队资料员停用、待整理、过期、失败、空库均明确显示状态。

本轮Wiki只读取既有库、图谱、正文及精确来源，不新增资料员、空间、宿主接口、模型请求或自动重编任务。继续使用既有知识API和 `SharedWikiGraph`，图谱关闭后移除观察器及消息监听；目标身份与异步代次校验防止串项目。编辑资料与整理策略仍由现有知识管理功能负责。

当前最小范围不再添加任务看板、独立文件管理器或另一套执行控制；有需要时先用折叠任务、历史和原生对话回溯，避免详情变成第二个工作台。

## 0.25.1 固定工作流与原生文字基线

本节取代前述按当前轨道预留 52/61/68/75px 行高、再向下平移最多 12px 的当前规则；旧节仅记录历史行为。当前轨道数量不得参与原生标题行的布局高度。

官方 `conversation.session.header.utilities` 中只保留稳定的插件占位，节点、名称与连接线在插件自有绝对定位层绘制。只读测量原生“轨迹”文字和自身名称的 Range 矩形，使步骤名称文字底部对齐原生文字底部；节点与普通顺序线随同一固定视觉层定位。回退箭头仅向上使用已有安全空间，不改变节点位置，也不推动原生标题、对话／轨迹、工具或正文。

绘制范围仍限制在原生 header 安全区域：不改宿主 DOM、祖先样式或原生组件；窗口、语言与字体变化重新测量，观察器在卸载时断开。无法完整容纳或端点不可见的回退路径不画，真实规则保留在无障碍说明和详情；没有页签时使用不会进入正文的降级布局。

验收以同一官方原生会话、“工作流：无”的宿主矩形为基线，直接比较零、一、三层和恢复零层的标题／页签／工具／正文位置；另比较节点行与文字底部、窗口滑动和实际验收状态变化。不再将每个场景分别与旧版本相同视为跨场景固定。

## 0.25.2 圆顶回退端口

回退线从源步骤圆最顶点 `(centerX, centerY - 14)` 出发，箭头竖直向下抵达目标步骤圆同一圆顶端口。自返工在圆上方绘制真实小环，起点和终点均为该圆顶，不退化为原路折返线。

首条轨道在圆顶上方 6px，后续轨距 5px；圆角 1px，为既有 5px 箭头保留完整向下线段。所有路径与箭头都在圆上方；描边余量、上方安全预算和不足空间时整线省略的规则保留。仅修改路径几何，固定 30px 占位、节点、名称及原生文字底部对齐均沿用 0.25.1。

## 0.25.3 详情与省略号中线

“详情”按钮只在自身视觉层按既有节点中心作垂直平移，元素中线与左右静态省略号及圆点中线保持一致。仍保留固定占位，不改变节点、名称、连线、原生标题／页签／正文的位置；没有省略号时按同一圆心中线定位。鼠标、键盘与详情对话框行为沿用现有入口。


## 0.26.0 同一库定义与项目引用

当前规则以 [ADR-002](../decisions/002-workflow-library-references.md) 为准，取代本页早期“全局编辑不影响已选副本”的约定。菜单只列 `workflowTemplates`，与 graph_horses 的顺序、ID、名称、版本一致；项目实例保存绑定与进度，`ProjectWorkflow` 是统一事务维护的执行投影，不是独立可编辑的另一份定义。旧项目独有定义一次性补入库，不复制整个项目、知识库或执行历史。

详情的步骤说明、交付内容和验收标准均默认独立收起，只在实际配置 `onRejectStepId` 时显示回退目标。顶部负责人来自当前步骤投影，不能用最近一条交付的员工冒充当前对接人。输入框上方只保留交付入口，不显示旧负责人／验收状态行。

项目知识库省略状态版本行和嵌套外框；图谱着色紧邻“知识图谱”，不再显示“返回全图”按钮，适配控件承接恢复全图、清除筛选与阅读焦点的行为。


## 0.26.1 对话页精简

原生输入框不再注册任务与交付 dock，也不再轮询最新任务。当前工作流的交付、验收和历史仍从顶部详情进入；独立任务的既有业务记录保留。首尾省略号以圆心为基准对称紧贴窗口边缘节点，详情向左使用尾部空白，负责人提示与详情文字左对齐。所有定位只影响插件自身元素，原生标题和标签位置保持不变。

## 0.29.1 本步骤返工显示简化

顶部工作流和详情竖向流程仅对跨步骤回退绘制虚线与目标提示。显式自退回与未配置目标时的默认本步骤返工都不占轨道、不画回环、不附加自退回的悬停或无障碍说明；只读步骤要求也不重复列出自身为退回目标。跨步骤目标、拥挤处理和点击查看保持原有行为。这里只调整显示，不改冻结定义、编辑器选项、验收和返工执行规则；取代历史段落中的自回环显示行为。
