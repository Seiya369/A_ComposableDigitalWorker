# 工作流步骤编辑

工作流页沿用自由职业人库的紧凑侧栏、标题及移除／导入／导出／保存按钮，无维度页签或保存成功横幅。标题右侧“引入团队”选择工作流使用的团队。主区只编辑步骤名称、负责人、步骤说明、交付内容、验收标准及不合格退回目标；支持添加、双向排序及确认移除，保留 1–50 步。

## 团队与负责人

未引入团队时，负责人控件禁用，只显示“请先引入团队”。引入在草稿中捕获 `WorkflowTemplate.team`：来源团队 ID、版本、名称，以及全部成员的 `memberId`、职业人模板引用、名称与 `reportsTo`。这是独立的组织关系快照，后续源团队调整不会静默改写工作流。成员复用职业人模板，未复制技能、模型凭据或另一套知识库。

`WorkflowRole.memberId` 将步骤角色定位到快照成员，`steps.roleId` 保持原契约。下拉框只显示引入团队的成员，并标明其上一级；不再提供自由职业人库或自定义负责人。更换团队优先按稳定成员和职业人身份匹配，只有唯一姓名才辅助匹配；无法匹配时先确认，再清空相关步骤负责人并禁止保存，直到重新选择。角色身份、名称都不能授予工具或数据权限。

团队选择弹框展示组织关系，支持取消、Escape、焦点返回和内部滚动；引入及更换仅修改草稿，明确保存后生效。旧流程如有唯一且步骤内容完全相同的既有团队绑定，可据此恢复负责人和团队；仅有名称或存在多个不同绑定时不会自动选择团队。没有团队的旧文档仍可读取和导出，界面再次保存前需明确引入团队。

## 步骤与流程图

步骤说明、交付内容、验收标准在宽屏等宽三栏，窄屏堆叠。交付内容和验收标准逐行编辑，在编辑期间保留 Enter 和末尾空行，提交时转为数组。未编辑的旧验收项、说明、角色说明、输入输出、超时和尝试上限保留。排序移动整个步骤对象，不重新创建步骤身份。

底部流程图按当前步骤顺序和负责人生成，随添加、移除、改名和排序同步；窄容器自动折行，箭头保持顺序连接，红色虚线标记不合格退回目标。点击节点定位对应步骤。流程图是配置预览，不表示任务已执行或已验收。

## 传输与执行边界

继续兼容 `graph_horses` v1：新版本接受可选团队快照及角色成员字段，旧无团队文档保持可读。工作流单独导出会带上全体成员引用的职业人配置及必要依赖；导入重新映射成员、上下级、角色和模板身份，先覆盖草稿，保存时原子提交。来源团队标识只作为追溯信息，快照不要求源团队仍存在。旧版插件不识别新增字段，含团队快照的文档需使用 0.14.0 或更新版本。

已有团队或项目的工作流副本保持冻结；本次编辑不自动执行工作、覆盖项目员工或改写历史副本。项目执行继续沿用已存在的成员映射、审批、验收和状态机。所有扩展位于本插件，通过既有公开 UI 槽和插件 API 运行，不修改 Harness 程序文件。

## 判断与返工

每步默认合格后进入下一步，末步完成流程；“不合格退回到”默认为本步骤返工，也可选择之前的步骤。配置使用稳定 `onRejectStepId`，不以会变化的序号存储。只允许本步骤或之前步骤，拒绝丢失及向前跳转的目标；重排不能使其失效，移除被引用步骤前明确确认，并把相关规则恢复为本步骤返工。所有全局／团队／项目绑定、导入和配置传输在生成新步骤身份时一并重映射此字段。含退回字段的配置需使用 0.15.0 或更新版本。

判断沿用项目的人工验收，不另开模型调用，也不宣称已实现任意条件表达式分支。点击“验收不合格”必须填写意见，流程先暂停等待处理；再点击“退回第 N 步返工”才真正开始返工。合格放行、暂停／恢复、取消、已有审批都保持。模型运行报错或取消只重试当前步骤，不会误当作质量判断退回。

确认退回时，将目标步骤至当前判断步骤全部置为待执行，由现有调度器顺序重新执行并逐步验收，禁止复用区间中旧结果作为新交接。此前已验收的尝试增加失效时间和原因，原员工任务、交付、验收和历史保持；失效结果退出当前已验证知识，即使自动归档开关关闭也撤销其有效证据。该撤销不删除历史原件。每个受影响步骤的累计尝试次数均受流程上限控制（默认 3 次），不因退回清零；任一步次数耗尽即阻止继续返工。命令仍校验项目、流程版本、当前任务和幂等身份；暂停中确认返工需恢复后才执行。

例如回归验证不合格退回缺陷修复，修复重做并验收后重新回归；若需修改需求或架构，先由负责人明确调整新工作流配置，运行中的冻结定义不被静默改写。
