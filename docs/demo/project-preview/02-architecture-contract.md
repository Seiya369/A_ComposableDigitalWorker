# 【演示资料】架构与接口契约

这是供架构师和开发人员阅读的演示设计稿，不是已完成实现的证明。

## 专业定义

官方扩展边界：仅通过公开插件、服务和 UI 插槽扩展宿主的边界。
插件入口：负责注册功能以及卸载时清理订阅、样式和后台任务的入口。
工作流实例：在项目中保留步骤、人员和团队版本的独立定义。
项目团队：项目内部的人员和组织关系快照。
组织结构：描述负责人及其直接、间接下级的有向层级。
乐观并发控制：通过预期版本拒绝覆盖其他写入的并发策略。
状态版本：描述某次完整状态提交顺序的单调版本。
交付契约：约束输入、输出、负责人和验收条件的步骤约定。

## 明确关系

官方扩展边界约束插件入口。
工作流实例保存交付契约。
工作流实例使用项目团队。
项目团队维护组织结构。
乐观并发控制保护状态版本。
插件入口遵守乐观并发控制。

## 演示接口约定

读取详情只投影当前工作流和所选步骤。写入同时携带项目、实例、步骤、工作单与版本；上下文或版本发生变化时，返回冲突并重新读取。

委派沿项目团队的组织结构进行。跨步骤协作需提供明确目标、输入引用和返回内容，不能凭岗位名称提高文件、网络或工具权限。

交付正文是只读快照；项目内路径只是引用，不能把存在一个路径等同于完成验证。卸载只清理插件专属数据，不删用户项目成果。
