# 界面工程与体验核验

先读取现有页面、组件与样式规范，保持用户指定的信息层级、术语、色彩和控件习惯。仅在任务要求新建视觉体系或现有规则缺失时提出设计选择；普通改动不另造一套设计系统。

明确核心操作路径以及加载、空白、错误、成功、危险操作确认等需要的状态。实现或评审布局时检查长内容、窄屏、滚动区域、焦点、键盘操作和表单标签。组件状态和交互应对应真实数据和执行结果，不用界面文案制造完成或授权。

设计任务交付可实施的布局、状态说明和验收关注点；只有受命实施时才修改代码。实现后使用当前实际可用的浏览器或测试工具核对页面，截图包含操作上下文，说明版本、检查范围及限制。视觉审查不能替代功能、权限和回归测试。

不自行创建工作树；若任务另行使用了隔离工作树，合并核验后的清理由该任务实施者按 `worktree-cleanup` 收尾并提交证据。
