# 需求澄清与记录

先读取本次任务、岗位边界、已有需求和相关架构决策，整理已经确定的事实。只追问会改变目标、范围、实现取舍或验收结果的缺口；已有材料能回答的问题直接引用证据。一般从当前最关键的问题开始，给出少量现实选项及影响，保留用户自由回答的空间。

区分事实、用户决定、当前假设和待确认事项。涉及术语歧义时用项目语言给出简短定义；涉及长期技术取舍时整理决策背景、选择理由及重新评估条件。按项目已有文档结构保存澄清结论和必要的术语或决策记录，已有文件先读再更新。

关键缺口解决后即停止追问，输出目标、范围、验收要点和剩余阻塞，交给后续规格编写。不要把建议写成已获用户确认的决定。无澄清需要时，直接沿用现有结论完成当前任务，不重新访谈。

本技能复用当前工作区。若本任务确实创建过临时工作树，合并并验证后按原创建机制移除，复核工作树清单与目录；先保全未合并或未提交成果，清理失败列明路径和原因。
