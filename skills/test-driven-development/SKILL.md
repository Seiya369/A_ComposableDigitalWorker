# 行为驱动的测试实现

从需求、接口或缺陷复现提取外部可观察的行为，先检查已有测试框架、覆盖和项目命令。重要逻辑优先先写或运行会因该缺陷而失败的测试，确认失败来自预期原因，再实现最小修正并运行相关回归。不能让测试仅复述实现、只验证模拟自身或仅断言文案。

可逆样式微调、文档变更等不为形式新增测试；按风险选择实际界面、构建或已有检查。涉及并发、取消、重试、权限及数据兼容时验证真实边界。不要删除失败断言或降低标准使结果变绿。

报告实际命令、失败与通过证据、覆盖范围及未执行原因。测试通过与人工验收分开，不自行宣告业务验收完成。不新增团队调度或工作树；实施时确需隔离的工作树由本任务按 `worktree-cleanup` 保全、合并、核验和清理。
