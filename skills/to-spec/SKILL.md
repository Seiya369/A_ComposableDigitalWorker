# 编写实施规格

根据任务中已经确定的目标、讨论结论、现有代码和项目文档合成规格。沿用项目术语和架构决策，明确哪些是已有事实、用户决定、建议方案和待确认假设。只有缺少会阻断实施或改变验收的关键信息时才集中询问，其余未知保留为带影响说明的待决项。

规格以用户可观察的行为为主体，写清问题、目标、范围、主要场景、输入输出、边界和失败处理。每项需求对应可验证的验收条件；补充必要的数据、接口、权限、兼容和迁移约束，避免把尚未验证的第三方能力写成现成接口。

测试安排优先使用已有的公开行为和验证入口，注明需要覆盖的正常、异常及恢复路径。文件路径、实现草案和示例仅在有助于表达具体决定时保留，不要求堆叠用户故事或扩展未授权需求。

将规格写入用户指定位置或项目已有规格目录，给出交付引用与未解决问题。默认产出本地文档；发布到外部工单系统另需该任务的明确授权。本技能复用当前工作区；本任务创建的临时工作树须在成果保全、合并验证后移除并复核，失败列明路径和原因。
