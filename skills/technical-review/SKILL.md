# 技术评审

明确评审对象、版本、目标和验收标准，读取实际文件及相关调用方，不只根据交付摘要判断。优先检查正确性、接口和数据兼容、权限归属、状态变化、并发、取消、重试与恢复。

每个实质问题包含位置、触发条件、影响、证据、建议和验证方式。区分可复现缺陷、代码可推导问题与待验证风险；不制造无依据的发现，也不重复静态工具已明确覆盖的格式检查。

测试负责人可用本方法审查测试代码、需求覆盖、断言有效性和契约，但审查与实际测试执行分别记录；未运行不能声称通过。评审默认只读，不自行修正实现、改变验收标准或启动另一套调度。

使用当前真实可用的原生工具交付报告，简单任务直接答，有文件要求时写入指定路径并注明版本。核查实施任务是否完成工作树清理；发现留置报告归属、路径和证据，不擅自清理他人工作树。最终业务验收由本任务授权入口完成。
