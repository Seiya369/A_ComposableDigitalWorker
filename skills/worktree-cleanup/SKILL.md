# 临时工作树收尾

此技能跟随创建工作树的实施、评审或发布任务。**合并完成不等于任务完成：本任务创建的临时工作树全部收尾后才算完成。** 只处理有本任务创建记录的路径；用户原有工作树、主工作树和其他任务的工作树保留。不要扫描并批量删除历史工作树。

使用当前岗位已有的工具与执行权限。没有 shell 或平台工作树管理权限时，交接明确路径和审计证据给有权限的执行者；在其确认清理结果前保留未完成项，不能宣称已经执行。

## 创建时登记

记录任务标识、仓库绝对路径、临时工作树绝对路径、创建时 HEAD、集成分支以及工具返回的归属信息。使用平台管理的工作树时，保留平台身份，收尾也使用平台提供的归档/移除入口，并检查物理目录与 Git 条目已经清理。平台只完成归档而仍有物理残留时，报告残留；先确认平台归属和清理机制，避免绕过平台管理。

普通 Git 工作树用随附 helper 直接创建并登记；它拒绝认领已有目录。先确定任务分支和集成分支，再运行：

```sh
node <本技能目录>/scripts/cleanup.mjs create --repo /绝对/主仓库 --worktree /绝对/临时工作树 --owner 本任务标识 --integration refs/heads/main --branch 本任务新分支
```

仅当本任务明确把某个根目录用作**可重新生成的依赖或构建缓存**时，在创建命令中追加 `--disposable-dir node_modules`，可重复指定。支持的目录以 helper 的 `--help` 为准；不要把交付物、用户上传、日志证据或不能重建的文件声明为可丢弃。默认连 ignored 文件也保留并阻断清理。helper 的创建记录位于仓库共享 Git 管理目录的 `workforce-temporary-worktrees/`，成功移除后清除该记录。

没有创建记录的现存目录只做只读检查，不能补写“本任务创建”记录来取得清理资格。helper 从指定集成分支的当前提交创建新分支；平台创建的工作树沿用平台归属和清理工具。

## 合并后清理

1. 确认交付物、验收证据和必要提交已进入指定集成分支或工作树之外的已核验保全位置。停止此工作树的 dev server、watcher 和子进程，退出该目录。
2. 对每个本任务拥有的路径运行 `audit`；参数使用创建时的同一组 `repo`、`worktree`、`owner`、`integration`。
3. 审计通过后以相同参数运行 `cleanup`。helper 使用原生 `git worktree remove`，不使用强制删除；只在登记明确允许且再次核验安全的目录内清除可再生 ignored 文件。
4. 以实际输出核对三件事：工作树物理路径不存在、Git 工作树列表不含该路径、该工作树的 Git 管理目录不存在。核对本任务登记清单已经没有未处置的临时工作树。

```sh
node <本技能目录>/scripts/cleanup.mjs audit --repo /绝对/主仓库 --worktree /绝对/临时工作树 --owner 本任务标识 --integration refs/heads/main
node <本技能目录>/scripts/cleanup.mjs cleanup --repo /绝对/主仓库 --worktree /绝对/临时工作树 --owner 本任务标识 --integration refs/heads/main
```

审计会阻断未合并提交、已修改或未跟踪文件、未声明的 ignored 文件、锁定工作树、隐藏索引改动、越界符号链接及生成目录中的嵌套或裸 Git 仓库。发现这些情况先保全并解决原因，不能通过 `--force`、直接递归删除整个工作树或清除所有工作树管理记录来绕过。

**Squash / cherry-pick：** helper 只接受工作树 HEAD 为集成提交祖先的证据，不把文本相似或 `patch-id` 相同当作已合并证明。此时保留目录，明确列出分支、HEAD、集成提交和未被祖先关系证明的内容；先把提交、tracked 差异、untracked 与 ignored 独占成果保全到工作树之外并核验恢复，再由用户明确认可此目标的清理方式。不要重置 HEAD 伪造审计通过。

结束时报告已清理的路径及核验结果。有失败时列出**具体剩余路径、阻断原因和保全状态**，任务不能声称“已彻底清除”。此技能不删除临时分支或提交对象，不声称回收共享 Git 对象库；目标是清除临时 checkout、依赖、构建目录及其专属管理条目。
