# 代码与测试审查

先确定任务范围、验收依据及比较基准，解析为固定提交。用户指定版本优先；未给出时可根据任务的原版、标签或分支证据推定，并在报告中说明依据。无法可靠确定时索取基准。读取仓库规范和相关调用方，以当前工作树为审查终点：包含基准以来的提交、暂存及未暂存改动，另检查范围内未跟踪文件。不能仅比较到 HEAD 而漏掉待交付内容。

分别核对需求是否实现，以及实现是否满足仓库规范、接口契约和数据边界。技术负责人重点审查设计、生产代码、权限、状态及失败恢复；测试负责人同样使用本技能审查测试代码、断言有效性、需求覆盖、边界和回归风险，检查测试是否真实触发被测行为、是否因过度模拟而掩盖缺陷。代码审查与实际测试执行相互补充。

每个发现提供优先级、文件与行位置、触发条件、实际影响、证据和修正建议。区分已复现缺陷、代码可直接推导的问题及待验证风险，说明未检查范围和未执行验证；没有实质问题时如实报告。

保持审查只读，不自行修代码、提交或发布。本技能不创建工作树；若本轮实施创建了临时工作树，核对合并后移除及目录复核的证据，未清理列为交付未完成项，交由创建者保全成果后清理。
